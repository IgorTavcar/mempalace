Surprises & Gotchas

The clever, the subtle, and the watch-outs.

This page is the highest-signal collection in the wiki: the non-obvious design choices, the “why is it written this way” moments, and the traps that bite you if you don't know they're there. Every finding is curated from the per-area deep dives and traced to a real line of code. If you only read one page to understand how MemPalace actually thinks, read this one — it's where the verbatim-always, local-first, never-corrupt philosophy meets the messy reality of ChromaDB internals, cross-platform shells, and weak local LLMs.

💡 Insights & clever patterns

💡 Insight

Raw verbatim text beats LLM-extracted memory by 2×. On LongMemEval, MemPalace's zero-LLM baseline hits 96.6% R@5 while extraction-based systems like Mem0 land at 30–45%. Extraction discards context: when an LLM extracts “user prefers PostgreSQL” and throws the conversation away, it loses why and what alternatives were weighed — and if the extraction fails, the original is gone forever. Storing everything verbatim and letting embeddings find it later is the simpler approach that wins, contradicting the field's consensus that AI extraction is required for memory. benchmarks/BENCHMARKS.md:1 · See Benchmarks

💡 Insight

Closets are a ranking SIGNAL, never a gate. The searcher always queries the full drawers collection first (the floor), then uses closet hits only to boost ranking — never to filter. A weak or missing closet pointer can therefore only help search, never hide a drawer that has strong BM25 signal. This is a deliberate rejection of closet-first / index-first RAG designs, which would suffer a “weak-closets regression” on narrative content whose regex-extracted closets are low-signal. searcher.py:823 · See AAAK Dialect & Closets

💡 Insight

The LLM is a scalpel, not a hammer — heuristic truth wins. During corpus-origin detection, the Tier-2 local LLM can extract persona names and platform, but its likely_ai_dialogue verdict is discarded if it disagrees with a confident Tier-1 regex heuristic. This protects against weak local models (e.g. a small Ollama model) flipping a confident answer. The careful non-overwrite merge keeps Tier-1's confidence while folding in Tier-2's platform/persona fields, and concatenates both evidence trails for auditability. cli.py:145 · See LLM Integration

💡 Insight

BM25 IDF is computed over the candidate set, not the corpus — and that's correct. Reranking applies BM25 to the small candidate set returned by vector search, computing IDF locally from those candidates. A term that's rare across the whole palace but common in this candidate set gets inflated IDF — which is exactly right for discriminating within these particular results. Computing IDF over the full corpus would be the “textbook” choice and the wrong one here. searcher.py:75 · See Search & Retrieval

💡 Insight

Date-only facts become full-day intervals at query time. A knowledge-graph triple stored as valid_from='2026-01-01' is normalized to ...T00:00:00Z, while valid_to='2026-01-01' becomes ...T23:59:59Z. So an as-of query using a precise UTC datetime still matches legacy date-only facts — a date is treated as a 24-hour window, not a single point. The trick lives in _temporal_start_key/_temporal_end_key and their SQL equivalents. knowledge_graph.py:56 · See Temporal Knowledge Graph

💡 Insight

The fact-checker uses two regex patterns, not NLP — on purpose. Contradiction detection recognizes only two surface forms (“X is Y's Z” and “X's Z is Y”, both resolving to the triple (X, Z, Y)). No parsing, no model. This is ultra-conservative by design: unrecognized relationship forms are silently missed (false-negatives) rather than misinterpreted (false-positives). A memory system would rather stay quiet than confidently flag a fake contradiction. fact_checker.py:47 · See LLM Integration

💡 Insight

Repair turns silent failures into queryable state. When extracted drawers have None or empty {} metadata (from sparse historical writes), repair doesn't drop them — it coerces the metadata to {"_repaired_empty_meta": True} so ChromaDB 1.5.x upsert validation passes. The sentinel is later discoverable via where={"_repaired_empty_meta": True}, so what would have been a vanished record becomes an auditable, filterable one. repair.py:150 · See Repair, Sync & Maintenance

💡 Insight

Multi-word entity candidates bypass the COCA stop-word filter. Single-word candidates run through the COCA content-word filter to suppress generic terms like “Code”, “Phase”, “Note”. But multi-word candidates skip it deliberately — otherwise “Claude Code” would lose its “Code” half. A conscious recall-over-precision trade for compound names. entity_detector.py:217 · See Entity System

⚠️ Gotchas

⚠️ Gotcha

Re-entrant locking prevents self-deadlock in the mine pipeline. The palace lock is tracked in a per-thread threading.local() set keyed by (pid, keys). The mine pipeline calls get_collection and then ChromaCollection.upsert, which tries to acquire the same lock from the same thread. Without the re-entrancy guard, the inner upsert would block on a second flock (Linux fcntl locks are per file descriptor) and deadlock a single thread against itself. The PID check also clears stale state after a fork so children re-acquire correctly. palace.py:509 · See System Architecture

⚠️ Gotcha

macOS bash 3.2 can't use mapfile — so the hook uses sed. macOS ships bash 3.2.57, frozen in 2006 at Apple's GPLv3 cutoff; mapfile/readarray only arrived in bash 4.0 (2009). The save hook parses Python output with sed -n 'Np' instead. If it had used mapfile, every hook value would silently fall back to its default on stock macOS, producing zero saves with no error (issue #1440). hooks/mempal_save_hook.sh:119 · See Hooks & Auto-save

⚠️ Gotcha

Windows can't probe a process with os.kill(pid, 0). On POSIX, signal 0 is a liveness check; on Windows, os.kill maps to TerminateProcess — so “checking” a PID would kill it. The code uses ctypes to call GetExitCodeProcess instead, returning False (dead) if the handle is invalid. A cross-platform landmine buried in a one-line utility. hooks_cli.py:342 · See Hooks & Auto-save

⚠️ Gotcha

Python's \b silently truncates names with combining marks. \b is a boundary between \w and non-\w, but Unicode Marks (categories Mc/Mn) are not \w — so a Devanagari name like अनीता gets clipped to अनीत at a word boundary. Hindi, Arabic, Hebrew, Thai, Tamil, Khmer and more are all affected. The fix — script-aware lookaround boundaries built from each locale's declared boundary_chars — is elegant but utterly non-obvious. i18n/__init__.py:119 · See Internationalization

⚠️ Gotcha

Switching embedding models silently breaks an existing palace. EmbeddinggemmaONNX.name() returns embeddinggemma_300m, and ChromaDB persists that name on the collection. Swap the model without rebuilding and ChromaDB rejects the collection on name mismatch — intentional, but surprising. The fix is to run mempalace repair rebuild-index. Worse, legacy palaces created before hnsw:space was mandatory silently default to L2/Euclidean; the cosine formula max(0, 1 - distance) then floors at 0 because L2 distances exceed 1.0, surfacing only as nonsensical relevance scores. embedding.py:159 · See Internationalization

⚠️ Gotcha

KG predicates are always lowercased and space→underscore normalized. Adding a triple maps “Child Of”, “child_of” and “CHILD_OF” all to the same predicate. This simplifies predicate discovery but will surprise callers expecting case preservation. Relatedly, the schema declares FOREIGN KEY (subject) REFERENCES entities(id) but the KG auto-creates missing entities on write — the foreign key is a soft, documentary constraint, so you can add triples for entities that don't yet exist. knowledge_graph.py:282 · See Temporal Knowledge Graph

⚠️ Gotcha

RTF files secretly bypass MarkItDown. MarkItDown 0.1.5 doesn't actually convert RTF — it returns the raw \rtf1\ansi control codes unchanged. The format miner detects .rtf and routes it to striprtf instead (verified live on a real RTF set, 2026-05-19). The per-format dispatch is invisible to callers: both paths emit Markdown that flows into the normal chunker, so a silent garbage-ingestion bug is averted by one suffix check. format_miner.py:387 · See Project Mining

⚠️ Gotcha

init isn't idempotent by default — it's made idempotent by filtering. Re-running init would otherwise pick up the entities.json and mempalace.yaml it wrote on the first run, changing corpus-origin density and producing a different classification. An artifact-skip filter excludes its own outputs to keep results stable — a subtle but critical detail for CI and multi-user teams. Note also that corpus-origin evidence is frozen once prefixed: --redetect-origin re-runs only Tier-1 heuristics, so evidence can't be upgraded post-init. cli.py:74 · See CLI & Onboarding

⚡ Performance

⚡ Performance

ChromaDB silently truncates results at 10K rows. col.get() caps out at 10,000 rows without raising, so _fetch_all_metadata paginates in 1,000-row batches to read everything. The warm metadata cache only applies when where=None — filtered queries always re-paginate fresh to avoid serving a stale subset. Relatedly, closet regeneration on 10k+ drawer palaces pages in batches of 5,000 to dodge SQLite's SQLITE_MAX_VARIABLE_NUMBER (32,766) ceiling that otherwise crashes ChromaDB. mcp_server.py:615 · See MCP Server & Tools

⚡ Performance

Absolute cosine similarity keeps ranking stable under candidate changes. Similarity is max(0, 1 - distance) — an absolute transform, not relative-to-max. If scores were (max_dist - dist) / max_dist, adding one very-close result would raise max_dist and reshuffle every other candidate's score. Absolute scoring guarantees that adding or removing a candidate never reorders the others, which is essential for predictable retrieval. searcher.py:160 · See Search & Retrieval

⚡ Performance

The HNSW divergence floor scales with the sync threshold. The corruption-detection floor is max(2000, 2 × sync_threshold) because ChromaDB batches flushes at sync_threshold intervals (raised to 50K to curb link_lists.bin bloat). A fixed 2000-record floor would flag every actively-written palace as diverged once its unwritten tail passed 1K records. Scaling with the threshold lets the probe tell normal flush-lag apart from real corruption (the 176K divergence in #1222). backends/chroma.py:567 · See Storage Backends

⚡ Performance

Emotion detection is keyword-based — zero tokens, instant, deterministic. Plain-text emotion tagging scans for 30+ lowercase keywords (love→love, feared→fear, happy→joy). No ML, no API call, capped at 3 deduped codes per line. It's a fast triage signal that costs nothing and is fully reproducible — the opposite of routing every line through a model. dialect.py:430 · See AAAK Dialect & Closets

⚡ Performance

The Stop hook runs async, PreCompact runs sync — a deliberate split. The Stop hook spawns mining in a detached background subprocess and exits immediately to stay under a ~500ms latency budget. The PreCompact hook uses synchronous subprocess.run, blocking until the mine completes — because compaction is about to destroy the transcript, so the data must be saved first. Latency optimization vs. data-safety, picked per hook. hooks_cli.py:472 · See Hooks & Auto-save

🔒 Security

🔒 Security

MCP stdio is protected at the file-descriptor level, not just in Python. The MCP server redirects stdout→stderr at both the Python level (sys.stdout = sys.stderr) and the FD level (os.dup2(2, 1)) before heavy imports. Transitive C libraries (ChromaDB→onnxruntime, posthog telemetry) print banners directly to fd 1, bypassing sys.stdout entirely — so a Python-only redirect would still corrupt Claude Desktop's JSON-RPC stream. The real stdout FD is saved and restored before the protocol loop. mcp_server.py:26 · See MCP Server & Tools

🔒 Security

The pickle health check never deserializes — it sniff-tests bytes. _segment_appears_healthy validates ChromaDB's index_metadata.pickle by checking only that it starts with 0x80 (pickle PROTO marker) and ends with 0x2e (STOP), detecting truncation or zero-fill without ever unpickling. This avoids arbitrary code execution from a malicious or corrupted pickle — a security-conscious choice for a routine integrity probe. backends/chroma.py:161 · See Storage Backends

🔒 Security

Non-HTTP LLM endpoints are rejected at parse time to prevent exfiltration. LLMConfig validates the endpoint scheme strictly: anything not http or https raises a ValueError on init. This rejects a misconfigured file:// LLM_ENDPOINT that could otherwise read and exfiltrate local files. Privacy by architecture, enforced at construction rather than at call time. closet_llm.py:109 · See Security & Privacy

🔒 Security

The query sanitizer turns a silent recall cliff into a graceful degradation. When AI agents prepend a 2000+ char system prompt to a 10–50 char question, the embedding model represents the whole string as one vector dominated by the prompt — recall collapses from ~90% to ~1% with no error (issue #333). The four-stage sanitizer (passthrough → question extraction → tail sentence → tail truncation) recovers to ~70–89%. Not perfect prevention, but a searchable degradation beats catastrophic silent failure. query_sanitizer.py:9 · See Security & Privacy
