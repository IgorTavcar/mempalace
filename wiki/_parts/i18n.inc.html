Cross-cutting

Internationalization

A multilingual memory: 14 UI locales, 100+ embedding languages, non-Latin entities.

MemPalace localizes UI strings and entity detection across 14 languages (en, ja, ko, zh-CN, zh-TW, de, es, fr, pt-br, it, ru, hi, id, be) via JSON catalogs in mempalace/i18n/. A single loader handles case-insensitive BCP 47 tags, dotted-key string interpolation, and language-aware entity patterns. Non-Latin scripts (Hindi/Devanagari, Chinese, Korean, Cyrillic, Belarusian) are kept intact through script-aware word boundaries that account for combining marks — Python's \b silently truncates them. For semantic retrieval, an optional multilingual embeddinggemma-300m model (0.88 cross-lingual cosine similarity) drops in beside the English-only all-MiniLM default.

How it works

Language loading & string lookup

load_lang(lang) reads JSON from mempalace/i18n/<lang>.json, normalizing the requested tag through _canonical_lang() so any capitalization resolves to the on-disk file. It stores the parsed locale in a module-level _strings dict and returns the full object. The t(key, **kwargs) function then navigates dotted keys (e.g. cli.mine_complete), performs {var} interpolation with kwargs, and falls back to the key itself if the string is missing. If a requested language has no file, English loads as the fallback so callers always get working strings — this is what wires up every localized message in the CLI.

Non-Latin script support in entity detection

Each locale's entity section may declare boundary_chars (the Unicode ranges that count as "inside-word" for that script), plus candidate_pattern and multi_word_pattern. The _script_boundary() function builds a lookaround regex that treats those characters as word-internal, so combining marks are preserved. Hindi declares boundary_chars="\wऀ-ॿ", which keeps the name अनीता intact instead of truncating it to अनीत. Boundaries are baked in during pattern collection (via _expand_b() and candidate wrapping) rather than patched up after matching.

⚠️ Python's \b silently truncates names with combining marks

\b is a transition between \w (Unicode Letter/Number) and non-\w, but Unicode Marks (categories Mc/Mn) — Devanagari matras, Arabic vowels, Hebrew points — are not \w. So a literal \bअनीता\b matches only अनीत, dropping the trailing ा. MemPalace's fix — script-aware lookaround boundaries (i18n/__init__.py:113) — is elegant but non-obvious; it is why entity extraction works for Hindi, Tamil, Thai, and similar scripts at all.

Entity pattern merging across languages

get_entity_patterns(languages) merges patterns from multiple locales into one dict. List fields (person_verb_patterns, pronouns, dialogue_patterns, …) are concatenated in request order with duplicates removed while preserving first occurrence; stopwords are returned as a sorted union; candidate_patterns and multi_word_patterns stay as fully-wrapped regex strings (boundaries and capture groups already applied), ready to compile directly. The consumers are entity_detector.detect_entities() and the entity system. Results are cached by canonicalized language tuple, so (pt-br, en) and (PT-BR, EN) share one entry.

Multilingual embeddings (EmbeddinggemmaONNX)

The EmbeddinggemmaONNX class wraps onnx-community/embeddinggemma-300m-ONNX, a quantized model supporting 100+ languages. It lazy-loads model and tokenizer from HuggingFace on first call, tokenizes input, runs ONNX inference, and truncates the 768-dim sentence embedding to 384-dim via Matryoshka Representation Learning so it slots into existing 384-dim ChromaDB collections without schema migration. The get_embedding_function() factory caches by (model, providers) tuple and falls back to all-MiniLM-L6-v2 when model='minilm' or unspecified. See LLM integration and storage backends for how these vectors feed semantic search.

Hardware acceleration & device resolution

_resolve_providers(device) maps device names (cpu, cuda, coreml, dml, auto) to ONNX Runtime execution-provider lists. The auto mode probes available providers in priority order (CUDA > CoreML > DirectML > CPU) and returns the first available. Unavailable accelerators emit a one-shot warning via a _WARNED set and fall back to CPU, so mining never fails because a GPU is missing.

Dialect compression with language context

The Dialect class accepts a lang parameter, loads the locale-specific AAAK instruction (t('aaak.instruction')) and regex patterns (get_regex()), and uses them to guide lossy compression. compress() extracts entities, topics, key sentences, emotions, and flags from plain text and returns AAAK Dialect format; the localized instruction is handed to LLMs as a system-level compression guideline (e.g. Japanese 概念間はパイプ vs English "pipes between concepts").

Key concepts

BCP 47 Language Tag
Standardized language code (RFC 5646), case-insensitive. MemPalace normalizes via _canonical_lang() so PT-BR, pt-br, and Pt-Br all map to the same file.
Combining Mark
Non-spacing diacritical mark (Unicode categories Mc/Mn) like a Hindi matra (ा) or Arabic vowel (َ). Python's \b word boundary ignores them, causing truncation; MemPalace fixes this via script-aware lookaround boundaries.
Script-Aware Boundary
A regex lookaround (?<=[chars])(?=[^chars]) that treats declared character ranges (e.g. Devanagari U+0900–U+097F) as word-internal, preserving combining marks and multi-codepoint names.
Entity Detection Patterns
Language-specific regex sets for candidate_patterns, person_verb_patterns, dialogue_patterns, project_verb_patterns, pronouns, and stopwords; merged per-language via get_entity_patterns().
Embedding Function (EF)
A ChromaDB-compatible callable returning vector embeddings. Two choices: minilm (384-dim, English-only, faster) or embeddinggemma (384-dim via Matryoshka truncation, multilingual, 0.88 cross-lingual cosine similarity).
Matryoshka Representation Learning (MRL)
A training technique that lets an embedding model produce useful outputs at any dimensionality. EmbeddinggemmaONNX truncates 768-dim output to 384-dim to be a drop-in ChromaDB replacement.
AAAK Dialect Instruction
A localized compression instruction stored in each locale's i18n JSON (e.g. Japanese vs English version), consumed by Dialect.compress() to guide LLM-based lossy summarization.
Entity Cache
The _entity_cache dict, keyed on tuple(languages), that caches merged entity patterns to avoid recompiling across get_entity_patterns() calls.

Implementation highlights

Script-aware word boundaries for combining marks. _script_boundary() (i18n/__init__.py:113) solves the combining-mark truncation problem by generating a lookaround that treats a locale-specific character class as word-internal. It is the single function that makes Devanagari, Arabic, Tamil, Thai, and similar names survive extraction.

mempalace/i18n/__init__.py:113 · script-aware word boundary for combining marks
def _script_boundary(chars: str) -> str:
    """Build a lookaround-based word boundary expression.
    Python's built-in ``\b`` ignores combining marks, so names like
    अनीता get truncated to अनीत. This returns a boundary that treats
    the declared chars as word-internal."""
    return (
        rf"(?:(?<=[{chars}])(?=[^{chars}])"
        rf"|(?<=[^{chars}])(?=[{chars}])"
        rf"|^(?=[{chars}])"
        rf"|(?<=[{chars}])$)"
    )

14 localized JSON catalogs with dual purposes. Each locale file (en.json, ja.json, hi.json, …) serves two roles: UI strings (terms, CLI messages, AAAK instruction) for the Dialect class and CLI, and entity-detection patterns (candidate_pattern, person_verb_patterns, boundary_chars) for mining. Colocating both avoids duplication and keeps the entity detector and Dialect using one source of truth.

Case-insensitive language-code normalization. _canonical_lang() (i18n/__init__.py:28) lowercases and glob-matches mixed-case codes to a single on-disk stem, applied in both load_lang() and get_entity_patterns() so any capitalization unifies through the loader and cache.

def get_entity_patterns(languages=("en",)) -> dict:
    # Normalize via canonical filename so "PT-BR" and "pt-br"
    # share one cache entry; unknown codes kept as-is so the
    # English fallback fires exactly once.
    languages = tuple(_canonical_lang(lang) or lang for lang in languages)
    key = languages
    if key in _entity_cache:
        return _entity_cache[key]
    # ... merge candidate/multi-word/verb patterns across locales,
    #     apply script-aware boundary expansion, union stopwords ...

    return merged

Lazy-loaded EmbeddinggemmaONNX model. _lazy_load() (embedding.py:170) defers downloading the ~300MB ONNX model and tokenizer from HuggingFace until the first __call__, so the import never blocks CLI startup and CPU-only users install without forced GPU dependencies. The output is truncated to 384-dim with outputs[self._output_idx][:, :_EMBEDDINGGEMMA_DIM] (embedding.py:220) and L2-normalized, matching MiniLM's vector width for drop-in compatibility.

mempalace/embedding.py:210 · ONNX inference, Matryoshka truncation to 384-dim, L2-normalize
def __call__(self, input):  # ChromaDB EF protocol uses `input`
    self._lazy_load()
    np = self._np
    texts = [_EMBEDDINGGEMMA_PREFIX + t for t in input]
    encs = self._tokenizer.encode_batch(texts)
    outputs = self._session.run(None, {...})
    sent_emb = outputs[self._output_idx][:, :_EMBEDDINGGEMMA_DIM]  # → 384d
    norms = np.linalg.norm(sent_emb, axis=1, keepdims=True) + 1e-12
    return (sent_emb / norms).tolist()
⚡ Multilingual embeddings trade speed for quality

EmbeddinggemmaONNX reaches 0.88 cross-lingual cosine similarity versus MiniLM's 0.35 on parallel-translated text (DE/FR/HI/IT/KO/RU), but it is slower: a 300MB lazy-downloaded model, a heavier tokenizer, and higher inference cost. Onboarding defaults new users to embeddinggemma and recommends it for non-English content, while existing palaces keep minilm for backward compatibility (embedding.py:140).

⚠️ The EF name is persisted in ChromaDB — switching models needs a rebuild

EmbeddinggemmaONNX.name() returns embeddinggemma_300m (embedding.py:159), and ChromaDB persists this on the collection. Swapping models without re-embedding makes ChromaDB reject the old collection on name mismatch. This is intentional — it forces mempalace repair rebuild-index (see maintenance) because the two models live in different vector spaces — but surprising if you don't expect it.

Candidate extraction edge cases & details
mempalace/entity_detector.py:181 · extract candidates with language-aware, unioned character classes
def extract_candidates(text: str, languages=("en",)) -> dict:
    patterns = get_entity_patterns(langs)
    stopwords = _get_stopwords(langs)
    coca_filter = _get_coca_filter()
    counts = defaultdict(int)
    for wrapped_pat in patterns["candidate_patterns"]:
        rx = re.compile(wrapped_pat)
        for word in rx.findall(text):
            wl = word.lower()
            if wl in stopwords or wl in coca_filter:  # block false positives
                continue
            counts[word] += 1
    return {n: c for n, c in counts.items() if c >= 3}

Single-word and multi-word patterns are unioned; the COCA frequency filter blocks common English words from masquerading as proper nouns, and only candidates appearing 3+ times are returned.

Design decisions

Localize UI strings and entity patterns in a single JSON structure per language.
Keeps all locale-specific data (UI, entity patterns, boundary_chars, AAAK instructions) colocated under one schema, avoiding definitions spread across files and making clear what is translatable vs structural.
Default multilingual embeddings (embeddinggemma) for new palaces, preserve minilm for existing ones.
0.88 cross-lingual similarity is a major quality win for non-English content, but existing palaces were built in MiniLM's vector space. Switching requires re-indexing, so onboarding offers and recommends embeddinggemma without breaking current users.
Script-aware boundaries via lookaround, not post-processing.
Baking boundary logic into the regex itself avoids slicing extracted names after the fact — names with combining marks are matched correctly the first time, not cleaned up later.
Lazy-load the EmbeddinggemmaONNX model on first use, not at import time.
A 300MB model should not block CLI startup or onboarding. Lazy loading lets CPU-only users run MemPalace without forced GPU dependencies and keeps import overhead minimal when the model is unused.
Cache entity patterns by canonical language tuple, allowing mixed case in callers.
BCP 47 tags are case-insensitive per RFC. Normalizing before cache lookup lets callers pass any capitalization and still share cached merged patterns, reducing redundant regex compilation.
💡 14 languages, but only 3 ship full entity patterns

Only zh-CN, hi, and ko declare boundary_chars and complete entity sections. ja.json and pt-br.json have no entity section at all, so they fall back to English entity patterns. Most locales translate UI strings (terms, CLI) but reuse English entity detection — a deliberate cost trade-off, not a bug. The merge loop's English fallback (i18n/__init__.py) is what keeps those locales working.

Data flow

Data starts in the locale JSON files (mempalace/i18n/*.json). load_lang() populates the module-level _strings dict, which t() reads for UI string lookups (e.g. cli.mine_start). Entity-detection patterns are extracted by get_entity_patterns(languages), which merges candidate_patterns, person_verb_patterns, and friends across requested locales, applies script-aware boundary expansion, caches by language tuple, and hands them to entity_detector.detect_entities() and palace.extract_entity_candidates(). Those patterns compile into regex objects applied to file content during mining and conversation mining.

In parallel, the embedding subsystem (embedding.py) supplies an EF — either EmbeddinggemmaONNX or minilm — to ChromaDB, which vectorizes text for similarity search and knowledge-graph queries. The Dialect class loads locale AAAK instructions (aaak.instruction) and regex (regex section) to drive lossy compression. Configuration (config.py) reads entity_languages and embedding_model from environment or config.json, letting users pick which languages' entity patterns apply and whether to enable multilingual embeddings.
