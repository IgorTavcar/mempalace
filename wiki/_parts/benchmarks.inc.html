Cross-cutting

Benchmarks

Reproducible recall numbers — and an unusually honest methodology.

MemPalace scores 96.6% recall@5 on LongMemEval using raw semantic search with zero API calls, demonstrating that storing verbatim conversation text and letting embeddings find it later beats LLM-based fact extraction. Layered heuristics — keyword overlap, temporal proximity, and preference extraction — push the number to 98.4% on held-out data and ≥99% with an optional LLM rerank, each improvement grounded in analysis of specific failure patterns. The suite spans three public academic datasets (LongMemEval, LoCoMo, ConvoMem) with published methodology, auditable per-question result files, and a deliberate refusal to teach-to-the-test for the final 0.6%.

How it works

The benchmark harness runs a tiered retrieval pipeline. A raw semantic baseline establishes the headline; a four-stage hybrid re-ranker layers targeted heuristics on top; a clean train/test split validates that the gains generalize; and an optional LLM rerank closes the last gap with semantic reasoning. Every layer is measured on the same datasets that drive the search and retrieval stack in production.

Raw semantic baseline: 96.6% with zero API calls

Each conversation session is stored as a single document containing all user turns concatenated. ChromaDB embeds documents and queries with sentence transformers (all-MiniLM-L6-v2, 384-dim) and retrieves by cosine similarity: the question's embedding is compared against all session embeddings, and the top-5 are returned. This baseline alone — no heuristics, no LLM, no API key — achieves 96.6% R@5 on 500 LongMemEval questions. The result contradicts the field's assumption that AI must extract and compress memory; verbatim storage avoids the information loss that extraction introduces.

💡 Insight: raw text beats LLM-extracted memory by 2.1×

On ConvoMem, MemPalace's verbatim approach scores 92.9% average recall versus Mem0's 30–45% (benchmarks/BENCHMARKS.md:109). Mem0 uses an LLM to extract structured memories; when that extraction fails, the original text is gone forever. MemPalace keeps the source text, so the embedding model can always find it later. The simpler design wins precisely because it discards nothing.

Hybrid v1–v4: targeted fixes for failure patterns

Each hybrid version targets a category of misses identified by error analysis, not individual questions:

  • v1 — keyword overlap scoring (0.30 weight × keyword match fraction reduces distance by up to 30%) for vocabulary mismatches like a "Business Administration" degree answer.
  • v2 — temporal date parsing and proximity boosting for time-anchored questions ("four weeks ago"); questions referencing the assistant trigger a two-pass retrieval.
  • v3 — 16 regex patterns extract preferences at ingest and create synthetic docs that bridge semantic gaps; rerank pool widens to top-20.
  • v4 — quoted-phrase extraction and person-name boosting for the final three failures.

Every fix through v3 is motivated by analyzing failure categories. The v4 step is the exception, and the authors flag it explicitly (see the integrity callout below).

Held-out evaluation: separating honest from overfitted

A train/test split (lme_split_50_450.json) ensures the hybrid improvements generalize. Researchers tune on 50 development questions, then evaluate on 450 held-out questions never seen during development. The held-out score of 98.4% R@5 is the honest publishable number, because all three misses that v4 targeted came from the same 500-question set used for validation — contaminating that result. The honest claim becomes "98.4% R@5 on clean unseen data; 100% if tuned on the test set itself."

LLM reranking: semantic reasoning over keyword matching

After hybrid retrieval produces a top-10 ranking, the full text of each candidate (capped at 500 chars) is sent to Claude Haiku with the question. Haiku returns a single session number (1–10) to promote to rank 1; all others stay in their hybrid order. This catches preference questions where embeddings fail due to vocabulary gaps — Haiku reasons about intent where embedding similarity cannot. The pass is optional and fault-tolerant: if the API call fails, the function returns the original hybrid ranking unchanged. See LLM integration for how Haiku/Sonnet are wired in.

⚡ Performance: rerank costs ~$0.001/query

The minimal 500-char-per-session prompt keeps the optional rerank cheap (~$0.001/query with Haiku, ~$0.003 with Sonnet) and errors rare. The headline 96.6% needs none of it — it reproduces on a laptop in five minutes with no API key.

Three academic datasets

LongMemEval (500 questions, ~53 sessions per query) tests single-needle-in-haystack retrieval across 6 question types. LoCoMo (1,986 questions over 10 long conversations) tests multi-hop fact connections and temporal inference. ConvoMem (75K+ QA pairs, 6 categories) tests scale and memory types — facts, preferences, changes, abstention. MemPalace scores 96.6% / 98.4% / ≥99% on LongMemEval (raw / hybrid / rerank), 88.9% R@10 on LoCoMo (hybrid, no rerank), and 92.9% average recall on ConvoMem. All three datasets are public; the benchmark code is deterministic and auditable.

Key concepts

Raw baseline (96.6% R@5)
Semantic search with ChromaDB's default all-MiniLM-L6-v2 embeddings over verbatim session text — no heuristics, no LLM calls. The reproducible, offline headline result.
Hybrid retrieval (98.4%)
Two-stage ranking: semantic retrieval of top-50 candidates, then re-scoring via keyword overlap (up to 30% distance reduction) plus a temporal-proximity boost for time-anchored questions.
LLM rerank (≥99%)
Optional third pass: send the top-K retrieved sessions to Claude Haiku with the question; Haiku selects the single most relevant session to promote to rank 1, leaving the rest of the ranking unchanged.
Held-out evaluation (98.4% R@5, 450q)
Clean train/test split: hybrid_v4 tuned on 50 dev questions, validated on 450 previously unseen questions to measure honest generalization.
Preference extraction
16 regex patterns detect how users phrase preferences ("I've been having trouble with X", "I prefer Y"); synthetic documents bridge vocabulary gaps between question phrasing and session text.
Two-pass assistant retrieval
For "what did you say" questions: pass 1 finds the top-5 sessions using user turns only; pass 2 re-indexes those sessions with full text (user + assistant) to avoid diluting the global index.
Recall@k vs QA accuracy
Retrieval recall measures whether the correct session is in the top-K; QA accuracy measures whether an LLM generates a correct answer. The metrics are independent — MemPalace's 96.6% is R@5, not end-to-end accuracy.
Benchmark integrity flag
Hybrid v4's last 0.6% came from analyzing three specific failed questions and building targeted fixes — teaching-to-the-test, acknowledged and disclosed rather than hidden.

Implementation highlights

The hybrid re-ranker's core is a single multiplicative fusion: a strong keyword match shrinks the semantic distance, but never enough to fully override a good embedding.

benchmarks/longmemeval_bench.py:624 · fuse semantic distance with keyword overlap
fused_dist = dist * (1.0 - hybrid_weight * overlap)
# dist:          ChromaDB cosine distance (lower = better)
# overlap:       fraction of question keywords in document (0.0-1.0)
# hybrid_weight: 0.30 (tuned via full 500-question validation)
# Result: perfect keyword overlap reduces distance by up to 30%

Keyword extraction deliberately strips noise. A 51-word stop list removes question markers, pronouns, prepositions, and temporal words, and only 3+ character words count, so a "perfect" overlap requires meaningful matches.

benchmarks/longmemeval_bench.py:553 · keyword extraction & overlap
def extract_keywords(text):
    words = re.findall(r"\b[a-z]{3,}\b", text.lower())
    return [w for w in words if w not in STOP_WORDS]

def keyword_overlap(query_kws, doc_text):
    doc_lower = doc_text.lower()
    if not query_kws:
        return 0.0
    hits = sum(1 for kw in query_kws if kw in doc_lower)
    return hits / len(query_kws)

Preference extraction runs at ingest. Sixteen regex patterns detect how users express preferences, and each match becomes a synthetic "User has mentioned: …" doc sharing the session's corpus_id (capped at 10 mentions). Evaluation deduplicates at the session level, so a preference doc and its source session both resolve to the same session.

benchmarks/longmemeval_bench.py:1138 · preference detection patterns
PREF_PATTERNS = [
    r"i(?:'ve been| have been) having (?:trouble|issues?|problems?) with ([^,\.!?]{5,80})",
    r"i(?:'ve been| have been) feeling ([^,\.!?]{5,60})",
    r"i prefer ([^,\.!?]{5,60})",
    r"i usually ([^,\.!?]{5,60})",
    r"lately[,\s]+(?:i've been|i have been|i'm|i am) ([^,\.!?]{5,80})",
    # ... 11 more patterns
]
for pat in PREF_PATTERNS:
    for match in re.findall(pat, text, re.IGNORECASE):
        mentions.append(match.strip())

Time-anchored questions get a temporal proximity boost. An 11-pattern parser resolves relative references ("N days ago", "a week ago", "last month") into a target date, and sessions inside the tolerance window earn up to a 40% distance reduction that decays linearly toward the window's edge.

benchmarks/longmemeval_bench.py:964 · temporal proximity scoring
delta_days = abs((sess_date - target_date).days)
if delta_days <= tolerance:
    temporal_boost = 0.40
elif delta_days <= tolerance * 3:
    temporal_boost = 0.40 * (1.0 - (delta_days - tolerance) / (tolerance * 2))
else:
    temporal_boost = 0.0
fused_dist = fused_dist * (1.0 - temporal_boost)
💡 Insight: temporal correctness is a hint, not a rule

The 40% cap (benchmarks/HYBRID_MODE.md:544) means an excellent semantic match can never be completely overridden by temporal proximity. This prevents a wrong-content session from the right date being promoted above a right-content session from a slightly off date.

Questions that reference the assistant ("you suggested…") use two-pass retrieval to avoid polluting the global index with assistant text.

benchmarks/longmemeval_bench.py:883 · two-pass assistant retrieval
if is_assistant_reference(question):
    # Pass 1: find top-5 sessions using user turns only
    results = collection.query(query_texts=[question], n_results=5)
    top_indices = [int(rid.split('_')[1]) for rid in results['ids'][0]]

    # Pass 2: reindex top sessions with full text (user + assistant)
    top_corpus_full = [corpus_full[i] for i in top_indices]
    collection2 = _fresh_collection('mempal_drawers_pass2')
    collection2.add(documents=top_corpus_full, ids=[f'doc2_{i}' for i in range(len(top_corpus_full))])
    results2 = collection2.query(query_texts=[question], n_results=n_results)
    two_pass_order = [top_indices[int(rid.split('_')[1])] for rid in results2['ids'][0]]
⚠️ Gotcha: global assistant indexing dilutes the signal

The naive fix — indexing all turns (user + assistant) globally — makes every session's assistant text compete with every other session's, drowning the semantic signal (benchmarks/BENCHMARKS.md:193). The two-pass approach finds the session first, then searches full text only within it, which outperforms global indexing precisely because it avoids that dilution.

⚡ Performance: the EphemeralClient singleton broke the memory wall

A module-level _bench_client = chromadb.EphemeralClient() (benchmarks/longmemeval_bench.py:97) is reused across all 500 questions, with collections deleted and recreated between queries. The previous PersistentClient-plus-tempdir pattern accumulated SQLite handles and crashed at Q388; switching to ephemeral eliminated the hang, made queries 2× faster, and enabled full 500-question runs.

More extractors: person names and quoted phrases (v4)

Person-name extraction (benchmarks/longmemeval_bench.py:1521) finds capitalized 3–15 character words, subtracting a 470+ line NOT_NAMES set ("What", "Monday", "January", "Previously"). Sessions containing any extracted name get a 40% distance reduction — this catches questions like "Rachel ukulele" where embeddings underweight proper nouns.

Quoted-phrase extraction (benchmarks/longmemeval_bench.py:1434) scans for single or double quoted phrases and gives a 60% boost to sessions containing the exact phrase — specialized for questions like "you suggested 'sexual compulsions'…" where the answer session contains the verbatim quote.

Design decisions

Publish raw 96.6% as the headline, not the reranked 100%
The 96.6% requires no API key, no cloud, and no LLM at any stage — it reproduces on a laptop in five minutes, aligning with MemPalace's local-first pitch. The reranked numbers are real but depend on an optional LLM. Leading with the harder constraint (offline, free) and noting the rerank as an upgrade is the honest framing.
Refuse to post cross-tool comparisons with Mem0, Mastra, Supermemory
Different systems publish different metrics on different splits — Supermemory and Mastra report QA accuracy, not retrieval recall. Placing R@5 next to QA accuracy is apples-to-oranges, so the authors decline to post comparisons they did not run under one metric on one dataset.
Commit every per-question result file and make it auditable
Aggregate numbers hide failure patterns. Committing JSONL files with every question, every retrieved document, and every score lets readers verify the claims rather than trust a scorecard — the core of the "honest benchmarks" ethos.
Implement a 50/450 train/test split after spotting v4 contamination
Once the teaching-to-the-test was recognized, the authors built a clean split rather than ignoring it: tune on dev (safe), publish on held-out (final). Benchmark integrity is treated as active, ongoing work.
Cap preference extraction at 10 mentions per session
Longer synthetic docs invite false-positive embedding matches. Capping at the 10 most salient preferences balances coverage against signal quality, and the cap is documented in code for review.
🔒 Benchmark integrity: 98.4% is the honest claim, not 100%

Hybrid v4's three fixes (quoted phrase, person name, nostalgia patterns) were developed by directly examining three specific failed questions — named in benchmarks/BENCHMARKS.md as d6233ab6, 4dfccbf8, ceb54acb (benchmarks/BENCHMARKS.md:489). That is methodological contamination: the fixes provably work on those three questions but may not generalize. The held-out 98.4% R@5 on 450 unseen questions proves v1–v3 generalize; v4's last 0.6% remains internally contaminated. The authors disclose this rather than hiding it.

Data flow

A question flows through a multi-stage pipeline:

  1. Raw semantic retrieval queries ChromaDB with the question embedding, returning the top-50 candidate sessions.
  2. Hybrid re-ranking applies keyword overlap and temporal proximity to those 50, producing a new ranked list.
  3. Two-pass assistant re-indexing runs if the question contains triggers like "you mentioned".
  4. Optional LLM reranking sends the top-10 sessions plus the question to Haiku, which returns a single session number to promote.
  5. Evaluation compares the final ranking against ground-truth session IDs, computing recall@k and NDCG@k.

Synthetic documents (preference docs, diary topics, quoted phrases) are indexed alongside session text under the same corpus_id, so they contribute to retrieval but map back to their session at scoring time. Result logs capture the full pipeline per question — the question, all retrieved documents, the final ranking, and the score — enabling the post-hoc analysis that powers MemPalace's transparency claims. These same retrieval layers feed the search and temporal knowledge graph subsystems.
