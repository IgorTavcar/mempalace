Cross-cutting

Security & Privacy

Privacy by architecture, plus the input-validation and hardening layers.

MemPalace is privacy-by-architecture: all data lives locally, there are no external APIs for core operations, and there is zero phone-home. That structural guarantee is reinforced by defense-in-depth: input-validation sanitizers (sanitize_name, sanitize_content), prompt-contamination mitigation (query_sanitizer), MCP stdio protection, symlink-attack rejection in export, hardened shell hooks, and strict 0o600/0o700 file permissions. The recurring theme is the same: make the unsafe code path impossible to reach rather than try to detect every attack.

How it works

Architectural privacy guarantee

MemPalace is privacy-by-design: all user data — drawers, the knowledge graph, embeddings, and indices — lives in ~/.mempalace/palace and never leaves the local machine. Core memory operations (mining, searching, embedding) run locally by default and require no cloud account or internet connectivity. External providers (Anthropic, OpenAI, Ollama) are supported only via explicit user configuration through env vars or config.json, and are never enabled silently. No telemetry library is imported. This eliminates the entire class of unintended exfiltration bugs — see System Architecture and LLM Integration.

Input validation at every boundary

All data entering the palace is validated through sanitizers in config.py before storage. Wing/room/entity names pass through sanitize_name(), which blocks path traversal (.., /, \), null bytes, and non-ASCII symbol characters, and enforces a 128-char limit. Content is validated with sanitize_content(), which rejects null bytes and enforces a 100 KB ceiling. Knowledge-graph values use sanitize_kg_value(), which is more permissive (allowing punctuation and slashes) but still rejects null bytes and over-length strings. All sanitizers call strip_lone_surrogates() to replace UTF-16 surrogates with U+FFFD before encoding, preventing ChromaDB encode crashes (#1235). The MCP server applies these validators to every tool input before any operation.

Prompt contamination prevention

Issue #333: when AI agents prepend system prompts (2000+ chars) to search queries, the embedding model represents the concatenated string as one vector where the prompt overwhelms the actual question, and retrieval collapses from 89.8% to 1.0% R@10. query_sanitizer.py implements a four-stage mitigation:

  • Passthrough — short queries (≤200 chars) are left untouched (no degradation).
  • Question extraction — for contaminated queries ending in ?, extract the question sentence.
  • Tail-sentence extraction — find the last meaningful segment.
  • Tail truncation — fallback: keep the last 250 chars.

With the sanitizer, worst-case recovery is ~70-80% — survivable — versus catastrophic 1.0% without. All four methods are logged, and sanitizer metadata is returned to the caller for transparency. See Search & Retrieval.

MCP stdio protection and Windows UTF-8 hardening

The MCP server (mcp_server.py:26-43) redirects stdout to stderr before importing heavy dependencies. Transitive imports such as onnxruntime or PostHog telemetry sometimes print banners to C-level stdout, which breaks Claude Desktop's JSON-RPC parser. The redirection happens at both the Python level (sys.stdout = sys.stderr) and the file-descriptor level (os.dup2(2, 1)), then the real stdout is restored in main() before entering the protocol loop. The _stdio.py module provides reconfigure_stdio_utf8_on_windows(), called by entry points (MCP server, CLI, fact_checker) to fix Windows ANSI codepage mojibake. Each stream can use a different errors= policy: the MCP server uses strict on stdout/stderr (bugs are loud), the CLI uses replace (verbatim text may contain surrogates), and stdin uses surrogateescape everywhere so malformed bytes survive as lone surrogates rather than raising UnicodeDecodeError. See Internationalization.

Symlink attack rejection and safe file I/O

The exporter.py module (lines 30-65) implements a two-stage symlink defense: _reject_symlink() pre-checks whether a path is a symlink, and _safe_open_for_write() uses O_NOFOLLOW (POSIX) or pre-check + open (Windows) at write time. On POSIX, open(O_NOFOLLOW | O_CREAT) fails atomically with ELOOP if the path is a symlink, closing the TOCTOU window between islink() and open(); files are opened with mode 0o600. The miner skips symlinks during project traversal (filepath.is_symlink() check, stderr warning). This defense-in-depth prevents symlink-based redirection attacks where a pre-placed symlink at the export output could write into /etc, /dev, or other system directories.

File permissions and state-directory hardening

Config files (~/.mempalace/config.json, ~/.mempalace/people_map.json) are created with 0o600 (owner read/write only). Directories (~/.mempalace) are created with 0o700. The exporter creates output_dir with 0o700 and all room files with 0o600. The save hook (mempal_save_hook.sh) uses umask 077 when creating hook_state files — atomically ensuring 0o600 — then chmod 600 as belt-and-suspenders. This prevents other local users on a shared box from reading config, people maps, or hook logs that reveal home paths and project structure. All chmod calls are wrapped in try/except for Windows, which does not support Unix permissions.

Hook script sanitization and validation

The mempal_save_hook.sh (lines 108-165) parses JSON input using Python (not shell eval), printing a parse-success sentinel followed by sanitized values. The shell reads via sed 'Np' (not mapfile, for bash 3.2 compat on macOS). If the sentinel is missing, the hook logs the failure and captures stderr to a file (mode 0o600) for debugging. Session IDs are sanitized to alphanumerics (issue #1231), and transcript paths are validated by _validate_transcript_path() in hooks_cli.py (suffix check: .json/ .jsonl only; .. rejection). See Hooks & Auto-save.

Key concepts

Privacy by architecture
The system physically cannot send data externally because it never leaves the local machine. No telemetry, no analytics, no phone-home. Core operations (mining, search, embedding, LLM calls) default to local-only; external providers require explicit user configuration.
Input validation sanitizers
Functions like sanitize_name(), sanitize_content(), and sanitize_kg_value() that enforce safe character sets, length bounds, null-byte rejection, lone-surrogate stripping, and path-traversal prevention at the API boundary.
Prompt contamination mitigation
A four-stage extraction pipeline in query_sanitizer.py that recovers user intent from queries contaminated by prepended system prompts, preventing retrieval failure (89.8% → 1.0% without, ~70-89% with the sanitizer).
MCP stdio protection
Redirects stdout to stderr before heavy imports so transitive dependencies (like onnxruntime or telemetry libraries) that print to C-level stdout cannot break JSON-RPC parsing in Claude Desktop.
Symlink rejection
Defense-in-depth guard that refuses to follow symlinks during export or file I/O; uses O_NOFOLLOW on POSIX systems to atomically reject symlinks at open time, closing the TOCTOU window.
File permission hardening
Config files, people maps, and exported directories are created with 0o600 (owner read/write only) or 0o700 (owner only) permissions, atomically via umask or os.open flags to prevent TOCTOU races.
Hook script sanitization
The bash save hook parses JSON input safely without eval, validates transcript paths (suffix checks, .. rejection), sanitizes session IDs to alphanumerics, and logs parse failures to aid debugging.
UTF-8 encoding hardening
Windows stdio reconfiguration to UTF-8 with per-stream error policies (strict on server, replace on CLI) and surrogateescape on stdin to survive malformed bytes without UnicodeDecodeError.
LLM endpoint validation
Rejects non-HTTP(S) schemes (file://, ftp://, etc.) in LLM_ENDPOINT to prevent misconfiguration from exfiltrating local files via a rogue endpoint.

Implementation highlights

Lone-surrogate stripping defense (#1235)

MCP clients (Claude Desktop, WorkBuddy) sometimes relay lone UTF-16 surrogates (U+D800–U+DFFF) when proxying binary input or corrupted clipboard data. str.encode('utf-8') raises on these, crashing ChromaDB add/upsert with -32000. The _LONE_SURROGATE_RE pattern replaces them with U+FFFD, ensuring all strings are legal UTF-8 before any operation.

config.py:29 · lone-surrogate stripping for UTF-8 legality
def strip_lone_surrogates(text: str) -> str:
    """Replace lone UTF-16 surrogates with U+FFFD so the string is legal UTF-8 (#1235)."""
    return _LONE_SURROGATE_RE.sub("�", text)
⚠️ The lone-surrogate bug came from MCP clients, not users

_LONE_SURROGATE_RE (config.py:22) exists because Claude Desktop and other MCP clients occasionally relay lone UTF-16 surrogates when copying binary or corrupted data from the clipboard. This is a platform quirk, not user error. Without strip_lone_surrogates(), ChromaDB crashes with -32000 on encode, making memory operations silently fail. The fix is one line but essential.

Path traversal prevention in sanitize_name()

sanitize_name() explicitly blocks .., /, and \ in a value, and the _SAFE_NAME_RE regex enforces a whitelist of allowed characters. Together they stop ../../etc/passwd-style attacks at the API boundary, before any file operation runs.

config.py:57 · path-traversal and null-byte rejection
    # Block path traversal
    if ".." in value or "/" in value or "\\" in value:
        raise ValueError(f"{field_name} contains invalid path characters")

    # Block null bytes
    if "\x00" in value:
        raise ValueError(f"{field_name} contains null bytes")

O_NOFOLLOW atomic symlink guard

On POSIX, os.open(O_NOFOLLOW | O_CREAT) fails atomically with errno.ELOOP if the path is already a symlink, eliminating the TOCTOU window. Windows (no O_NOFOLLOW) pre-checks with os.path.islink(), which is narrower but sufficient. File descriptors are opened with 0o600 for owner-only write access.

exporter.py:52 · O_NOFOLLOW atomic symlink guard for POSIX
    o_nofollow = getattr(os, "O_NOFOLLOW", 0)
    if o_nofollow:
        flags = os.O_WRONLY | os.O_CREAT | o_nofollow
        flags |= os.O_APPEND if "a" in mode else os.O_TRUNC
        try:
            fd = os.open(path, flags, 0o600)
        except OSError as e:
            if e.errno == errno.ELOOP:
                raise ValueError(f"refusing to write: {path!r} is a symbolic link.") from None
🔒 Symlink rejection closes the TOCTOU window atomically

A naive islink()-then-open() sequence leaves a time-of-check-to-time-of-use gap an attacker can exploit. By passing O_NOFOLLOW into os.open() itself, the kernel atomically refuses to open a symlink, so a pre-placed symlink at the export target cannot redirect writes into /etc or /dev. The islink() pre-check remains only as a fallback on platforms without O_NOFOLLOW.

The MCP server attaches this as query_sanitized metadata in results so users know when contamination was detected and which method recovered intent.

💡 A searchable degradation beats silent failure

Issue #333 showed that without sanitization, system-prompt-contaminated queries drop to 1.0% retrieval — complete failure. With the four-stage sanitizer, worst-case (tail-truncation fallback) is ~70-80%, and common cases (question extraction, tail sentence) hit 85-89%. Perfect detection of contamination is impossible without an adversary model, so the system trades certainty for survivable, observable degradation.

Hook JSON parsing without eval

Instead of eval'ing generated code, the hook uses json.load(sys.stdin) to parse safely, then re.sub() to sanitize each field (session_id to alphanumerics, transcript_path to safe chars). A parse-success sentinel (__MEMPAL_PARSE_OK__) lets the shell distinguish "parsing succeeded" from "Python crashed", preventing silent failures (mempal_save_hook.sh:150).

⚠️ macOS bash 3.2 forbids mapfile

macOS ships bash 3.2.57, frozen in 2006 at the GPLv3 cutoff. The mapfile/readarray builtins only arrived in bash 4.0 (2009). The save hook can't use them; instead it parses Python output with sed -n 'Np' to read individual lines into shell variables. On stock macOS, mapfile would silently fail, defaulting every hook value and producing zero saves (#1440).

More surprises & edge cases
⚡ Stdio redirection must work at the file-descriptor level

mcp_server.py redirects stdout to stderr at both the Python level (sys.stdout = sys.stderr) and the file-descriptor level (os.dup2(2, 1)). The fd-level redirect is required because transitive C libraries (onnxruntime, telemetry) print directly to fd 1, bypassing Python's sys.stdout. Skipping the fd-level redirect would still corrupt the JSON-RPC stream.

💡 Transcript-path validation is mirrored in shell and Python

The shell hook (mempal_save_hook.sh:219-230) and _validate_transcript_path() in hooks_cli.py:124 enforce the same checks: .json/.jsonl suffix only, no .. traversal segments. This is deliberate defense-in-depth — the shell guards input to the Python mining commands, and Python validates separately, so either layer can catch a breakout attempt.

Design decisions

Privacy by architecture — data never leaves the machine by design
The CLAUDE.md principle is "Local-first, zero external API by default." The whole system is built to run offline; mining, search, embedding, and (optionally) LLM calls default to local execution, and no telemetry library is imported. Exfiltration cannot happen because the code path does not exist. External providers are opt-in only, requiring explicit env-var configuration.
Sanitize at input boundaries, not at storage
All sanitizers live in config.py and run at the API boundary (MCP tool inputs, CLI args, hook scripts). Invalid data is rejected before it can be stored or used, which means the miner, searcher, and storage backends can trust their inputs.
Query sanitizer uses heuristic recovery, not cryptographic certainty
Perfect detection of system-prompt contamination is impossible without an adversary model. The system uses pragmatic heuristics — short queries are likely clean, questions (?) are likely real intent, tail sentences are likely the query — with tail truncation as the worst-case fallback. This trades perfect detection for survivable degradation (70-89% vs 1.0%).
Symlink rejection uses O_NOFOLLOW on POSIX, pre-check on Windows
POSIX O_NOFOLLOW closes the TOCTOU window atomically at open time; Windows lacks it, so pre-checks are necessary. The exporter uses both (pre-check always, plus O_NOFOLLOW when available), keeping the logic consistent across platforms.
Hook scripts use Python inline for parsing, not bash eval
Shell escaping is error-prone, so the save hook parses JSON with json.load() and sanitizes fields with regex, avoiding eval entirely. The shell reads sanitized values back using sed (bounded, deterministic), limiting the blast radius of any parsing bug to the Python inline script rather than the whole hook.

Data flow

User-supplied data enters through three channels: (1) MCP tools (mempalace_add_drawer, mempalace_search, …), (2) CLI commands (mine, search, export), and (3) auto-save hooks (mempal_save_hook.sh). All input passes through sanitizers in config.py before use: names through sanitize_name(), drawer content through sanitize_content(), temporal values through sanitize_iso_temporal(). Search queries are additionally processed by query_sanitizer to recover intent from prompt-contaminated input.

Sanitized data is written to the palace (ChromaDB drawers, the SQLite knowledge graph, AAAK indices) with strict file permissions (0o600/0o700, atomically via umask or O_NOFOLLOW). All disk writes are local-only; no network calls occur for core operations. Exported data is streamed to markdown files with symlink-attack prevention. Hook scripts run in the background, mining transcripts and project files, and their JSON input is parsed safely via Python (not eval) and logged to ~/.mempalace/hook_state/ with strict permissions. At no point does user data leave the local machine unless the user explicitly configures an external LLM endpoint — which is validated to use http/https only.
