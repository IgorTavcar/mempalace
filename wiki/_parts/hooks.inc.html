Hooks & Auto-save

Background filing that keeps memory off the chat window and under budget.

MemPalace ships two Claude Code hooks — Stop and PreCompact — that auto-save session transcripts into the palace without blocking the chat. The Stop hook checkpoints every 15 human messages; the PreCompact hook saves everything just before context compression. Both mine the JSONL transcript directly into drawers, then notify the AI via a tiny systemMessage (silent mode, default since v3.3.0) or, in legacy mode, block the AI to save via MCP tools. By writing diary entries through a direct Python API call instead of asking the AI to retype them in chat, this design saves roughly USD 1 per session.

How it works

Both hooks read a JSON event from stdin (containing session_id, transcript_path, and stop_hook_active), validate that the palace exists, then either mine in the background (Stop) or synchronously (PreCompact). The split is deliberate: Stop optimizes for latency, PreCompact optimizes for data safety. Hooks are wired through the CLI dispatcher and feed the conversation miner.

Stop hook: every N messages

After each assistant response Claude Code fires the Stop hook. The hook counts human (non-command-message) entries in the JSONL transcript; if the count since the last save is >= SAVE_INTERVAL (15, configurable) it triggers a checkpoint. It logs state, derives the project wing name from the transcript path, and spawns detached background mines for both the transcript (convos mode) and an optional MEMPAL_DIR (projects mode). Then it either saves a diary entry directly (silent mode) or returns decision: block to ask the AI to save manually (legacy mode).

  • Threshold-based: fires at 15, 30, 45… exchanges.
  • Counts only human (non-command-message) entries.
  • Derives wing from transcript cwd metadata first, falling back to path decoding.
  • Spawns background mines asynchronously via _spawn_mine; skips if the target is already running.
  • Silent mode (default): Python API save, zero chat-window cost. Legacy mode (opt-in): blocks the AI until manual save via MCP tools.

The stop_hook_active flag prevents infinite loops: when the AI tries to stop again after saving, the flag is already true and the hook lets it through.

PreCompact hook: emergency save before compression

When the context window fills, Claude Code fires the PreCompact hook with the transcript path. Unlike Stop, it does not count messages or gate on a threshold — compaction always warrants capture — so it runs a synchronous (blocking) mine of the transcript and optional MEMPAL_DIR, then returns {} to allow compaction to proceed.

  • Synchronous mine: blocks the hook until complete.
  • Always runs (no threshold or gate).
  • 60-second timeout per mine target.
  • Ensures the transcript is physically filed before the AI loses access to it.
💡 Insight — Stop runs async, PreCompact runs sync

The Stop hook spawns mines via _spawn_mine (detached subprocess) and exits immediately to stay under the 500 ms budget. The PreCompact hook uses subprocess.run and blocks until the mine completes. Stop optimizes latency; PreCompact optimizes safety — it must wait so the transcript is saved before compaction loses it. The same two events, opposite execution models. See hooks_cli.py:472.

Per-target PID deduplication

Hook-spawned miners claim atomic PID slots in ~/.mempalace/hook_state/mine_pids/ to prevent concurrent mines of the same source (which would corrupt the HNSW index). The hook hashes the mine command (dir + mode + wing) into a slot filename, then tries to atomically create a PID file with O_CREAT | O_EXCL. If the file already exists and its PID is alive, the spawn is skipped; if the PID is dead, the slot is reclaimed via unlink-and-recreate. A stored timestamp enables stale-by-age detection (default 2 hours, MEMPALACE_MINE_TIMEOUT_HOURS=0 disables it).

  • Hash digest of the mine command yields a unique slot per (dir, mode, wing).
  • Atomic O_CREAT | O_EXCL prevents race conditions between simultaneous hook fires.
  • Stale detection by PID liveness or age (default 2 hours).
  • Child removes its own slot on exit via the MEMPALACE_MINE_PID_FILE env var.
  • Distinct targets run in parallel; the same target is deduped.

Silent mode vs. blocking (legacy)

Silent mode (hook_silent_save=True, default since v3.3.0) calls tool_diary_write from the MCP server directly as a Python function, then returns a systemMessage like ✦ N memories woven… so the AI sees only a notification. Blocking mode (legacy) returns {"decision": "block", "reason": …} to ask the AI to save manually via mempalace_diary_write / mempalace_add_drawer; the AI stops and must save before proceeding. The config defaults to True to match the MISSION.md goal of removing noise from the chat window.

⚡ Performance — ~USD 1/session saved

Previous versions asked the AI to write diary entries in chat, costing roughly USD 1 per session in token retransmission. Silent mode saves directly via the Python API (tool_diary_write), so the AI never writes diary blocks in chat — the only output is a negligible systemMessage notification. This single change justifies the shift from blocking to silent mode (MISSION.md:30).

Detached subprocess lifecycle

Hook-spawned mines detach fully from the harness via platform-specific mechanisms. On POSIX, Popen uses start_new_session=True so signals (SIGTERM, SIGINT) don't propagate from the hook to the child. On Windows it sets creationflags with DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_BREAKAWAY_FROM_JOB so the child doesn't inherit stdout/stderr handles and the parent can exit. The child redirects to hook.log and cleans up its own PID slot on exit via _cleanup_mine_pid_file(). The hook process exits immediately while mining continues in the background.

Configuration & kill-switch

Hooks respect the hooks.auto_save boolean (default True, read from ~/.mempalace/config.json or env var MEMPALACE_HOOKS_AUTO_SAVE). When auto_save=False both hooks return {} immediately with no mining or side effects. The palace-root kill-switch (_palace_root_exists()) checks that ~/.mempalace is a directory; if the user removes or clears it, all hooks short-circuit before any disk access — even before logging the short-circuit — preventing accidental recreation. This lets users disable MemPalace entirely without uninstalling the hook scripts. See Security & Privacy and Maintenance.

Shallow-path guard & Python resolution

Claude Code's harness may inherit a minimal PATH (e.g. /usr/bin:/bin on macOS GUI launch) lacking the user's venv, so hooks must resolve the correct interpreter themselves. _mempalace_python() resolves in priority order: (1) MEMPALACE_PYTHON env var, (2) venv under the package install path (parents[3]/bin/python for site-packages installs), (3) project-relative venv (parents[1]/venv/bin/python for editable installs), (4) sys.executable fallback. It checks len(parents) before indexing to avoid IndexError on shallow paths (Docker /work, /opt/app), per PR #1580 review. Shell hooks (mempal_save_hook.sh) use the same resolution and pass MEMPALACE_PYTHON into the subprocess env.

Implementation highlights

Detached subprocess creation. A single helper produces the Popen kwargs that fully detach a child so the hook can exit, branching on os.name for Windows vs. POSIX (hooks_cli.py:27):

hooks_cli.py:27 · detached Popen kwargs (POSIX / Windows)
def _detached_popen_kwargs() -> dict:
    """Kwargs that fully detach a Popen child so the hook process can exit."""
    kwargs: dict = {"stdin": subprocess.DEVNULL, "close_fds": True}
    if os.name == "nt":
        flags = 0
        for name in ("DETACHED_PROCESS", "CREATE_NEW_PROCESS_GROUP", "CREATE_BREAKAWAY_FROM_JOB"):
            flags |= getattr(subprocess, name, 0)
        if flags:
            kwargs["creationflags"] = flags
    else:
        kwargs["start_new_session"] = True
    return kwargs

Atomic PID slot claim. _create_mine_slot_with_placeholder reserves a per-target slot with os.open(..., O_CREAT | O_EXCL | O_WRONLY, 0o600), recording PID and creation timestamp. The caller, _claim_mine_slot, falls back to stale-reclaim logic when the slot already exists (hooks_cli.py:433):

hooks_cli.py:433 · atomic PID slot claim with stale reclaim
def _claim_mine_slot(cmd: list[str]) -> Optional[Path]:
    """Atomically reserve the per-target PID slot for ``cmd``.
    Returns the slot path on success, or ``None`` if already running."""
    pid_file = _pid_file_for_cmd(cmd)
    pid_file.parent.mkdir(parents=True, exist_ok=True)
    try:
        return _create_mine_slot_with_placeholder(pid_file)
    except FileExistsError:
        pass
    if _mine_already_running(cmd):
        return None
    try:
        pid_file.unlink()
    except FileNotFoundError:
        pass
    try:
        return _create_mine_slot_with_placeholder(pid_file)
    except FileExistsError:
        return None

Palace-root kill-switch. Every entrypoint (hook_stop, hook_session_start, hook_precompact) calls this first; is_dir() (not exists()) treats a stray file or broken symlink as absent (hooks_cli.py:48):

hooks_cli.py:48 · user-removable kill-switch

    return PALACE_ROOT.is_dir()

Silent-mode save. When silent mode is active, the hook writes the diary entry through a direct Python call and only emits a systemMessage when something was actually saved (hooks_cli.py:942):

Under the hood, _save_diary_direct (hooks_cli.py:649) imports mcp_server.tool_diary_write, extracts the last 30 user messages, infers themes via _extract_themes (hooks_cli.py:632, top 3 by frequency after a 300-word English stopword filter), and writes a compressed checkpoint entry (CHECKPOINT:date|session:X|msgs:N|recent:…). The themes are appended to the systemMessage to hint the AI about what was saved.

⚠️ Gotcha — Windows can't use os.kill(pid, 0)

On POSIX, liveness is checked with os.kill(pid, 0). On Windows, os.kill with a signal maps to TerminateProcess — it would kill the process. The code uses ctypes to call GetExitCodeProcess instead, returning False (dead) if the handle is invalid. This cross-platform difference is buried in a utility function (hooks_cli.py:342) but is critical for correctness.

⚠️ Gotcha — macOS bash 3.2 has no mapfile

macOS ships bash 3.2.57 (Apple's 2006 GPLv3 cutoff), which lacks mapfile/readarray (bash 4.0+). The shell hook parses Python output with portable sed -n 'Np' instead. Without this, every parsed value would fall back to its default on macOS and hooks would silently produce zero saves (issue #1440). See mempal_save_hook.sh:118.

Shell-hook parsing & defense-in-depth

The shell hook (mempal_save_hook.sh:150) parses JSON via inline Python, emitting a __MEMPAL_PARSE_OK__ sentinel followed by sanitized values, one per line. Shell reads the sentinel via sed -n '1p' to distinguish "Python failed" from "parsing succeeded but the value is empty." Hardening includes umask 077 on the stderr redirect, printf '%s' instead of echo, and a 4 KB cap on the error log.

Design decisions

Background detached subprocess vs. inline synchronous mining
Hooks must return to Claude Code within 500 ms. Spawning a detached subprocess lets the hook exit immediately while mining continues. PreCompact is the exception — it mines synchronously because compaction must wait for the transcript to be saved. The split respects both latency and data safety.
Silent mode (Python API) as default, blocking mode (MCP) as legacy
Per the MISSION.md goal of removing chat-window noise and eliminating token retransmission, silent mode saves via a direct Python call at zero token cost. Blocking mode asks the AI to save via MCP tools but costs tokens and interrupts flow, so it is opt-in for backward compatibility.
Per-target PID slots instead of a global mine.pid
Different targets (dirs, modes, wings) must run in parallel; a single global file would either block unrelated targets or allow concurrent miners of the same target — corrupting the HNSW index. Per-target slots, claimed via atomic O_CREAT|O_EXCL, give parallelism across targets and deduplication within a target.
Palace-root kill-switch (empty ~/.mempalace check)
Removing ~/.mempalace is the user-visible way to disable MemPalace without uninstalling hooks. The check runs before any side effect — even logging — so the absence signal itself is never recorded, fully respecting user intent.
Wing derivation: cwd metadata → path decoding → fallback
Wing names aren't provided by the harness, so they're inferred from the transcript. cwd metadata is the most reliable source; path decoding is a heuristic fallback for transcripts outside .claude/projects; wing_sessions is the last resort. This hierarchy prioritizes correctness and avoids silent misclassification.
💡 Insight — safe defaults on a broken config

If hook_silent_save is unreadable (missing, corrupted, or raises AttributeError), the code defaults to True — silent mode — rather than blocking (hooks_cli.py:900). A broken config saves in the background instead of trapping the user in an infinite block loop or losing data. Likewise, wing derivation reads cwd metadata first because Claude Code records the working directory on most message types (hooks_cli.py:839), making it the most reliable signal.

Data flow

User sends a message → Claude Code fires the Stop hook (or PreCompact) → hook_stop() / hook_precompact() reads stdin JSON (session_id, transcript_path, stop_hook_active) → the hook validates that the palace root exists and checks hooks_auto_save → it counts human messages via _count_human_messages → if the count >= SAVE_INTERVAL (or always, for PreCompact) it derives the wing via _wing_from_transcript_path → it claims an atomic PID slot and spawns a detached subprocess via _spawn_mine (or, for PreCompact, runs the mine synchronously with subprocess.run) → the mine ingests the transcript (convos mode) and optional MEMPAL_DIR (projects mode) into palace drawers.

In silent mode the hook then calls _save_diary_direct → mcp_server.tool_diary_write → a diary entry is written to the wing → the hook returns {systemMessage: "✦ N memories…"}. In blocking mode it returns {decision: block, reason: …} → the AI saves via MCP tools → the AI retries Stop → stop_hook_active=true lets it through → data persists in drawers and diary. For PreCompact the transcript is filed before compaction proceeds. Logs land in ~/.mempalace/hook_state/hook.log and PID slots in the mine_pids/ subdirectory. See the full architecture and conversation mining for the downstream stages.

💡 Insight — 30s harness limit, 60s+ mine

The hook command timeout in .claude/settings.local.json is 30 seconds (the harness kills the hook past that). But the mine subprocess can run 60+ seconds (timeout=60 in the PreCompact subprocess.run, or unlimited when MEMPALACE_MINE_TIMEOUT_HOURS > 0.05). The Stop hook spawns the mine and exits; the mine runs independently in the background. This keeps hook latency under the 500 ms budget while still allowing substantive work (hooks/README.md:30).
