MCP Server & Tools

Around 29 Model-Context-Protocol tools that let an agent live inside the palace.

The MCP server (mcp_server.py, 2,869 lines) exposes the entire palace read/write/knowledge-graph interface as JSON-RPC tools for Claude Code and Claude Desktop. It implements stdio protection to block transitive dependencies from corrupting the JSON-RPC stream, cache invalidation to detect external database writes, aggressive retry logic for ChromaDB and knowledge graph stale handles, and a write-ahead log for audit trails. The 29 tools span palace reads (list/search/traverse), writes (add/update/delete drawers, sync), graph mutations with temporal filtering, cross-wing tunnels, agent diaries, and maintenance.

How it works

Protocol loop and request dispatch

main() restores the real stdout, configures UTF-8 on Windows, starts the idle watchdog, then enters an infinite loop reading JSON-RPC requests from stdin. handle_request() routes initialize/ping/tools/list/tools/call methods, validates parameter types against each tool's input schema, whitelists unknown arguments, and returns JSON-RPC responses. The server never exits cleanly — it either crashes, hits KeyboardInterrupt, or the idle watchdog exits after the timeout.

Stdio protection at startup

Before any imports, the module saves the real stdout (fd 1) via os.dup(), redirects fd 1 to fd 2 (stderr), and sets sys.stdout = sys.stderr. This prevents chromadb/onnxruntime from writing C-level stderr banners onto the live JSON-RPC stream. In main(), _restore_stdout() undoes both the Python-level and fd-level redirects, restoring the real stdout for JSON-RPC output. Embedded interpreters without fd support are caught and silently skipped.

🔒 Security

ChromaDB → ONNX/posthog and other transitive dependencies write banners to stdout at the C level (not via Python), breaking Claude Desktop's JSON-RPC parser. The fix at mcp_server.py:26 uses os.dup2 before imports — redirecting sys.stdout alone does not catch fd-level writes from C libraries, and the redirect must happen at import time, not in main().

Cache management and staleness detection

_get_client() compares the current inode and mtime of chroma.sqlite3 against cached values. An inode change (full rebuild) or an mtime change (external write, > 10ms delta) triggers a ChromaDB client rebuild. Before opening the client, _refresh_vector_disabled_flag() probes HNSW capacity via a pure sqlite/pickle read — never touching chromadb — so the issue #1222 divergence flag is set before the segment loads. _get_collection() retries once on any exception, clearing caches to force a fresh chromadb rebuild on the second attempt. Metadata is cached for 5 seconds and invalidated on writes.

💡 Insight

_refresh_vector_disabled_flag() (mcp_server.py:350) reads pure sqlite + pickle metadata straight out of chromadb's segment files to detect index divergence without opening a PersistentClient. This gates the client open and avoids segfaults on load (issue #1222) — the probe is a pure filesystem read with zero chromadb interaction.

Knowledge graph threading and retry

_call_kg(op) captures the canonical KG path once (realpath + normcase), then runs op(kg) via _get_kg(). If a sqlite3.ProgrammingError (closed database) is raised, it evicts that kg instance from the per-path cache and retries once. The canonical path is threaded through both _get_kg calls to prevent insert/evict key drift if env or mounts change between attempts. The underlying KnowledgeGraph uses a per-instance threading.Lock and WAL mode for concurrent access. See the temporal knowledge graph for the storage side.

Tool implementation: read, write, KG, tunnels, diaries

Read tools (status, list_wings/rooms, search, traverse) pull from ChromaDB collection metadata or KG SQLite without modifications. Write tools (add_drawer, delete_drawer, update_drawer) log to the WAL before mutations, detect idempotency via a col.get() probe, and invalidate the metadata cache. KG tools (kg_query/add/invalidate/timeline) go through the _call_kg wrapper. Tunnel tools (create/list/delete/follow) read and write tunnels.json with id canonicalization. Diary tools use timestamp-based unique ids for append-only entries, storing parent_entry_id for chunked reconstruction.

  • Idempotency: add_drawer checks drawer_id and last_chunk_id before insert to avoid re-filing identical content.
  • Chunking: content larger than chunk_size is split into bounded per-chunk drawers in a single batched upsert (all-or-nothing).
  • Sanitization: all inputs pass sanitize_name/content/kg_value; lone surrogates are stripped before write.

Warmup and idle watchdog

_maybe_eager_warmup_embedder() (opt-in via MEMPALACE_EAGER_WARMUP=1) pre-loads the embedder and HNSW segment at startup, paying both the ONNX cold-load tax (5–30s) and the segment load cost before the first tool call, preventing -32000 timeout errors on large existing palaces. _start_idle_exit_watchdog() spawns a daemon thread that checks _last_request_time every 60s and calls os._exit(0) if idle longer than MEMPALACE_MCP_IDLE_HOURS (default 8h, set to 0 to disable), releasing ChromaDB file handles on Windows.

Key concepts

MCP Protocol
Model Context Protocol — a JSON-RPC 2.0 request/response interface over stdio for Claude Code and Claude Desktop to invoke tools without network round-trips.
Stdio Protection
Redirection of stdout at the file-descriptor level (os.dup2) before heavy imports, preventing transitive dependencies (chromadb, onnxruntime) from writing banners/errors that corrupt JSON-RPC payloads.
Cache Invalidation
Detection of external writes via inode + mtime checks on chroma.sqlite3, forcing a ChromaDB client/collection rebuild to prevent stale HNSW indices.
Retry-on-Close
A one-shot retry pattern in _call_kg for sqlite3.ProgrammingError when a KnowledgeGraph handle is closed mid-operation (a race between tool call and reconnect).
Write-Ahead Log (WAL)
A JSONL audit trail at ~/.mempalace/wal/write_log.jsonl recording all drawer/KG mutations with content redaction for review and rollback.
AAAK Dialect
A compressed memory format using entity codes (ALC, JOR), emotion markers (*warm*, *fierce*), and pipe-separated fields for agents to write dense diary entries. See AAAK Dialect & Closets.
Tunnel
An explicit cross-wing connection (stored in tunnels.json) linking rooms that relate across projects/domains, complementing the implicit graph edges from rooms spanning multiple wings. See the palace model.
Idle Auto-Exit
A daemon watchdog thread that exits the MCP process after MEMPALACE_MCP_IDLE_HOURS (default 8h) with no requests, releasing ChromaDB file handles on Windows.

Implementation highlights

Stdio protection via os.dup2 — Lines 26–43 redirect stdout to stderr before imports to block transitive-dependency banners from corrupting JSON-RPC. The file-descriptor level (os.dup) is essential because some C libraries write to stderr directly, bypassing Python's sys.stdout. _restore_stdout() undoes both the fd and Python-level redirects in main().

mempalace/mcp_server.py:26 · redirect fd 1 → fd 2 before imports
_REAL_STDOUT = sys.stdout
_REAL_STDOUT_FD = None
try:
    _REAL_STDOUT_FD = os.dup(1)
    os.dup2(2, 1)
except (OSError, AttributeError):
    pass
sys.stdout = sys.stderr

Inode + mtime staleness detection — _get_client() detects external database modifications (CLI, scripts, repair) by comparing the current st_ino and st_mtime against cached values. FAT filesystems returning 0 for st_ino are guarded (line 474), and _vector_disabled_flag is refreshed before the chromadb client open (line 482) to catch HNSW divergence before segment load.

mempalace/mcp_server.py:474 · inode + mtime detection
inode_changed = current_inode != 0 and current_inode != _palace_db_inode
mtime_changed = current_mtime != 0.0 and abs(current_mtime - _palace_db_mtime) > 0.01

if _client_cache is None or inode_changed or mtime_changed:
    _refresh_vector_disabled_flag()
    _client_cache = ChromaBackend.make_client(_config.palace_path)

Retry-on-close for KnowledgeGraph — _call_kg wraps all KG operations with a one-shot retry on sqlite3.ProgrammingError. The canonical path is captured once (line 276) and threaded through both _get_kg calls (lines 278, 284) to prevent key drift if env mutates between reconnect and retry.

mempalace/mcp_server.py:276 · canonical path threading + one-shot retry
path = _canonicalize_kg_path(_resolve_kg_path())
for attempt in range(2):
    kg = _get_kg(path)
    try:
        return op(kg)
    except sqlite3.ProgrammingError:
        if attempt == 0:
            with _kg_cache_lock:
                if _kg_by_path.get(path) is kg:
                    _kg_by_path.pop(path, None)
            continue
        raise
⚡ Performance

_call_kg retries at most once on sqlite3.ProgrammingError (line 282) rather than spinning — a second close is a lost race, not a transient. The tradeoff is that a reconnect-during-handler still fails on the second attempt, but it avoids hung loops (line 263).

Write-ahead log with content redaction — _WAL_DIR (~/.mempalace/wal, line 390) stores JSONL entries. _wal_log redacts content/query/entry fields (lines 406–409) via the _WAL_REDACT_KEYS frozenset, replacing values with '[REDACTED N chars]'. The log file is created atomically via os.open with O_CREAT|O_WRONLY and mode=0o600 (line 401).

Chunked content with idempotency probe — tool_add_drawer handles oversized content (> chunk_size) by splitting into bounded chunks in a single batched upsert (line 1219). The idempotency probe checks both drawer_id (single-chunk) and the last chunk_id (chunked) to re-detect prior writes, and physical chunk ids are returned in the response for fetch/delete iteration.

mempalace/mcp_server.py:1170 · idempotency probe before batched upsert
if len(content) <= chunk_size:
    idempotency_probe_ids = [drawer_id]
else:
    last_chunk_idx = (len(content) - 1) // chunk_size
    idempotency_probe_ids = [drawer_id, f"{drawer_id}_chunk_{last_chunk_idx:06d}"]
try:
    existing = col.get(ids=idempotency_probe_ids, include=[])
    if existing.ids:
        return {"success": True, "reason": "already_exists", "drawer_id": drawer_id}
⚠️ Gotcha

_fetch_all_metadata paginates col.get() in 1000-row batches (line 621) because ChromaDB silently truncates results at 10K rows without raising. The warm metadata cache only applies when where=None (line 649) — filtered queries always paginate fresh to avoid returning a stale subset.

💡 Insight

Agent diaries normalize agent_name to .lower() at write (line 1617) and read (line 1745) so Claude, claude, and CLAUDE all resolve to the same diary (issue #1243). This breaks pre-fix mixed-case entries unless repaired, but keeps future reads robust; filters apply on wing + room='diary' + agent (lines 1758–1760).

Design decisions

Write-ahead log (WAL) for all mutations
Provides an audit trail for detecting memory poisoning and enables review/rollback without touching the vector index. Content is redacted to avoid logging sensitive user data. Local-first storage means the log is operator-accessible and never auto-purged — the trust boundary is the user's machine. See Security & Privacy.
Retry-on-close instead of preventive locking
The KnowledgeGraph can close between _get_kg() and the op(kg) call during reconnect. A one-shot retry is simpler than RWLock + readers/writers semantics and preserves the contract that reconnect cleanly resets state without leaking handles. Spinning/hung loops are worse than a single clear failure.
Inode + mtime staleness detection over file watches
Stateless detection works across platforms (including Windows FAT), needs no background threads, and handles both full rebuilds (inode) and in-place modifications (mtime). It avoids filesystem-watch API complexity and platform-specific TOCTOU races, and is cheap (one stat syscall) before every chromadb touch.
Metadata cache with 5-second TTL over always-fresh
Metadata changes on every write, yet status/list_wings/list_rooms/get_taxonomy all read it. Always-fresh would require paginating 1000+ drawers on every read; a 5-second TTL balances freshness with latency, and the cache is invalidated immediately on writes (lines 1194, 1228, 1268, 1459, 1310).
Opt-in eager warmup instead of blocking main
Cold ONNX load (5–30s) plus HNSW segment load can exceed the MCP client timeout (issue #1495). Eager warmup pays both costs at startup but is opt-in via MEMPALACE_EAGER_WARMUP to preserve default startup latency — users with large existing palaces set the flag; fresh installs don't pay the cost.

Data flow

Requests enter main() as JSON lines on stdin. handle_request() parses the JSON-RPC envelope, routes to the TOOLS dict, and invokes the handler with type-coerced arguments (integers, floats from the transport). Read tools query _get_collection(), which polls _get_client() for cache validity via inode/mtime, returning the cached ChromaDB collection with metadata filtered by wing/room. Writes log to the WAL, mutate via col.upsert/delete/update, then invalidate _metadata_cache. KG tools wrap mutations in _call_kg(op) with one-shot retry on close. Tunnel tools read/write tunnels.json. Diary tools append via col.add with parent_entry_id linkage for chunked reconstruction. All responses are serialized to JSON with ensure_ascii=False (literal UTF-8) and written to stdout with a flush. Transitive-dependency writes are redirected to stderr at startup, and _restore_stdout() restores the real fd 1 in main() before the loop. The vector path delegates to hybrid search and pulls clients through storage backends.
