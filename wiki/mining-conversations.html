Conversation Mining

Normalizing AI chat transcripts and filing them verbatim, message by message.

MemPalace converts diverse chat export formats — Claude Code JSONL, ChatGPT, Gemini CLI, OpenAI Codex, Slack, and Claude.ai JSON — into a canonical >-prefixed transcript via the --mode convos pipeline. The primary miner chunks by exchange pair (question + answer) or extracts five memory types in general mode, while a secondary sweeper catches per-message outliers that fall between file-level chunk boundaries. A separate diary path files daily summaries atomically per day with SHA-256 change detection, and an RFC 002 adapter contract opens the door to pluggable third-party sources.

How it works

Conversation mining is a multi-path pipeline. Files enter through scan_convos, are auto-detected and normalized to a transcript, then chunked into drawers within the palace model. Two ingest paths run independently — a fast file-level miner and a resume-safe message-level sweep — plus a dedicated diary ingest. Unlike project mining, which chunks at fixed character size, conversation mining preserves conversational structure as the primary unit.

Format detection & normalization

The normalize function (normalize.py:113) auto-detects the export format from file extension and content shape, then dispatches to format-specific parsers (Claude Code JSONL, ChatGPT mapping tree, Gemini CLI, Slack JSON export, and more). Each parser extracts (role, text) message pairs and converts them to the canonical >-prefixed transcript. System tags, hook output, and tool-result content are selectively stripped or truncated to remove noise without losing substance.

normalize.py:632 · role/text pairs → >-prefixed transcript
def _messages_to_transcript(messages: list, spellcheck: bool = True) -> str:
    """Convert [(role, text), ...] to transcript format with > markers."""
    lines = []
    i = 0
    while i < len(messages):
        role, text = messages[i]
        if role == "user":
            if _fix is not None:
                text = _fix(text)
            lines.append(f"> {text}")
            if i + 1 < len(messages) and messages[i + 1][0] == "assistant":
                lines.append(messages[i + 1][1])
                i += 2
            else:
                i += 1
        else:
            lines.append(text)
            i += 1
        lines.append("")
    return "\n".join(lines)

Primary file-level mining

After normalization, content is chunked by chunk_exchanges (convo_miner.py:138), which detects Q+A pairs (lines starting with >) and groups each user turn with the AI response that follows as a single unit. If fewer than three quote-marker lines are found, the fallback chunks by paragraph breaks, then by line groups for content without paragraph structure. The _emit_bounded helper keeps each chunk within the CHUNK_SIZE limit (800 chars) while respecting MIN_CHUNK_SIZE (30 chars), never silently dropping trailing text. On each drawer upsert, room detection scores content against topic keywords (technical, architecture, planning, decisions, problems) and hall detection routes via cached config keywords.

convo_miner.py:174 · exchange-pair chunking, AI response preserved verbatim
def _chunk_by_exchange(lines: list, chunk_size: int, min_chunk_size: int) -> list:
    """One user turn (>) + the AI response that follows = one or more chunks."""
    chunks = []
    i = 0
    while i < len(lines):
        line = lines[i]
        if line.strip().startswith(">"):
            user_turn = line.strip()
            i += 1
            ai_lines = []
            while i < len(lines):
                next_line = lines[i]
                if next_line.strip().startswith(">") or next_line.strip().startswith("---"):
                    break
                if next_line.strip():
                    ai_lines.append(next_line.strip())
                i += 1
            ai_response = " ".join(ai_lines)
            content = f"{user_turn}\n{ai_response}" if ai_response else user_turn
            _emit_bounded(chunks, content, chunk_size, min_chunk_size)
        else:
            i += 1
    return chunks

Idempotent rebuild on schema bump

When NORMALIZE_VERSION increments (e.g. v1 → v2), prefetch_mined_set (palace.py:813) scans the palace once to collect every source file already mined at the current version in a single paginated query, avoiding O(n) per-file lookups. For any source file not in that set, the file-level miner purges all prior drawers via _source_file_delete_ids (which handles legacy extract_mode absence) before upserting fresh chunks. Stale-version hits in file_already_mined return False, triggering purge-before-insert so pre-v2 drawers never survive alongside v2 drawers from the same source.

⚡ Performance

prefetch_mined_set (convo_miner.py:608) turns an O(n) flood of per-file queries into one paginated scan. On a 150k-drawer palace with 2000 files, swapping ~2 s-per-file lookups for a single pass saves roughly an hour of wall-clock time per ingest run.

Message-level sweep (secondary path)

The sweep function (sweeper.py:193) provides a second ingest path that bypasses file-level chunking and processes per-message records directly from Claude Code JSONL. For each session_id it fetches the max timestamp of existing drawers (the cursor), then iterates the JSONL. Each message gets a deterministic drawer ID keyed by (session_id, message_uuid), so reruns automatically deduplicate via pre-flight existence checks — making the sweep idempotent and resume-safe. This keeps the primary miner fast and simple while the sweep runs independently on JSONL sources; the two coordinate only through deterministic IDs, never shared state.

sweeper.py:268 · cursor-based skip logic for idempotent sweep
for rec in parse_claude_jsonl(jsonl_path):

    if sid not in cursors:

    cursor = cursors[sid]
    if cursor is not None and rec["timestamp"] < cursor:
        drawers_skipped += 1
        continue
    drawer_id = _drawer_id_for_message(sid, rec["uuid"])
    document = f"{rec['role'].upper()}: {rec['content']}"
    metadata = {
        "session_id": sid,
        "timestamp": rec["timestamp"],
        "message_uuid": rec["uuid"],
        "role": rec["role"],
        "source_file": source_label or jsonl_path,
        "filed_at": datetime.now().isoformat(),
        "ingest_mode": "sweep",
    }
💡 Tie-break safety: < cursor, not ≤ cursor

The sweep skips messages with timestamp < cursor (strictly earlier), not ≤ cursor. Multiple messages can share one ISO-8601 timestamp; if only some siblings were ingested before a crash, a ≤ skip would lose the rest forever. Skipping with < lets the deterministic drawer IDs deduplicate exactly at the cursor boundary on re-run, so resumption never drops data (sweeper.py:20).

Diary ingest with incremental detection

Daily summary files (*.md in the diary dir) are split on ## entry headers by ingest_diaries (diary_ingest.py:102) and stored as per-entry drawers. The function tracks entry count and a SHA-256 content hash in a per-(palace, diary-dir) state file under ~/.mempalace/state/. On re-run, if the hash matches and force=False, the file is skipped entirely. If the hash differs, a full rebuild purges all prior drawers for that source file before fresh entries are written. New entries are packed into closets — indexed summaries in the AAAK dialect — atomically grouped by topic without splitting mid-topic.

state_key = f"{wing}|{diary_path.name}"
prev_entry = state.get(state_key, {})
prev_hash = prev_entry.get("content_hash")
curr_hash = hashlib.sha256(text.encode("utf-8")).hexdigest()
if not force:
    if prev_hash is not None:
        if curr_hash == prev_hash:
            continue
content_changed = prev_hash is not None and curr_hash != prev_hash
full_rebuild = force or content_changed
if full_rebuild:
    try:
        drawers_col.delete(where={"source_file": source_file})
    except Exception as exc:
        logger.debug("legacy purge skipped for %s: %s", source_file, exc, exc_info=True)

RFC 002 plugin scaffolding

The sources/ module defines the BaseSourceAdapter contract (base.py:164), registry discovery via entry points (registry.py), a transformation pipeline (transforms.py), and a PalaceContext facade (context.py:48). Third-party adapters register through setuptools entry points (mempalace.sources) and declare their metadata schema, supported modes (chunked_content / whole_record), and transformations (utf8_replace_invalid, whitespace_collapse_internal, strip_tool_chrome, …). A conformance suite verifies that adapter output can be reproduced from source bytes using only the declared transformations, in order. Adapters yield SourceItemMetadata ahead of DrawerRecord for lazy-fetch optimization, and core checks is_current to skip already-ingested items; an empty declared_transformations set marks a byte-preserving adapter.

Key concepts

Exchange pair
One user turn (prefixed >) plus the AI response that follows; the primary chunking unit in conversation mining, preserving Q+A semantics rather than arbitrary character boundaries.
Extract mode
Chunking strategy: exchange (default) preserves conversation structure, while general applies heuristic keyword matching to extract five memory types (decisions, preferences, milestones, problems, emotional) with per-chunk classification.
Normalization
Format auto-detection and conversion of diverse chat export schemas (7+ formats) to a canonical >-prefixed transcript with noise stripping and tool-result truncation.
Drawer sweep
Timestamp-coordinated, idempotent message-level ingestion that catches individual messages missed by file-level chunking; uses a cursor and deterministic IDs to resume cleanly after crashes.
NORMALIZE_VERSION
Schema versioning constant (v2) that gates incremental ingest and triggers auto-purge of pre-v2 drawers on schema bumps, preventing mixed old/new rows in the same source.
Wing resolution
Heuristic routing that auto-defaults conversation files from .claude/projects, .codex, or .gemini to wing_api, with fallback to dirname-based slugification for other sources.
Closet packing
Atomic grouping of diary topics into fixed-character closets (indexed summaries) that never split mid-topic, with full rebuild on content changes to prevent orphaned closets.
Incremental state
Per-(palace, diary-dir) state file tracking content hash and entry count to skip unchanged diary files and detect in-place edits without re-ingesting entire days.
RFC 002 source adapters
Pluggable ingestion contract (BaseSourceAdapter) for third-party sources (Cursor, GitHub, Slack APIs) with declared transformations, metadata schema, and privacy class.

Implementation highlights

Noise stripping: line-anchored patterns only

All noise-removal patterns (_NOISE_TAG_PATTERNS, _NOISE_LINE_PATTERNS, _HOOK_LINE_RE, _COLLAPSED_LINES_RE) are anchored to line boundaries and refuse to cross blank lines (normalize.py:40). This prevents a stray unclosed tag or malformed hook line in one message from eating content in adjacent messages. After stripping, consecutive blank-line runs collapse to at most three blank lines (strip_noise, normalize.py:93).

Tool-result formatting: head/tail windows

Bash tool results are sampled with a head (20 lines) plus tail (20 lines) window when output exceeds 40 lines, with a marker for omitted lines (normalize.py:564). Grep/Glob results cap at 20 matches. Read/Edit/Write results are omitted entirely (the content already lives in the palace or git). Unknown tools fall back to a 2048-byte cap. Crucially, this truncation is applied per-message and never across message boundaries.

⚠️ Slack speakers are positional, not verified

Slack exports have no inherent user or assistant role. The parser (normalize.py:446) assigns alternating roles to distinct speaker IDs and prefixes each message with the speaker ID so downstream chunking (which relies on > markers) still works. A provenance footer marks the transcript as Slack-imported so consumers know the speaker roles are positional, not authenticated.

Per-chunk memory-type rooms

In general extract mode, chunks from general_extractor carry a per-chunk memory_type — decision, preference, milestone, problem, or emotional (convo_miner.py:419). Rather than assigning a single file-level room, each chunk's memory_type becomes its drawer room, and room-count deltas accumulate per chunk rather than per file, allowing fine-grained room stats.

Edge cases & details
  • Wing resolution heuristic (convo_miner.py:456): _is_ai_tool_path detects .claude/projects (not .claude itself), .codex, and .gemini path segments; _resolve_wing then defaults such sources to wing_api, grouping Claude Code, Codex, and Gemini conversations under one wing. Other sources fall back to normalize_wing_name on the directory basename.
  • Honest rerun metrics (sweeper.py:183, sweeper.py:237): sweep_id = f"sweep_{session_id}_{message_uuid}" and a pre-flight existence check count new vs. already-present rows separately, so rerun counts never inflate.
  • Stale-drawer purge (convo_miner.py:395): legacy drawers without extract_mode metadata are treated as exchange mode for cleanup, allowing old/new coexistence only within the current schema.
  • Diary full rebuild on in-place edits (diary_ingest.py:171): if the content hash changes but entry count stays the same, a full rebuild still fires and purge-before-insert (diary_ingest.py:205) clears orphaned closets.
  • Legacy state fallback (diary_ingest.py:152): state without content_hash falls back to size comparison, then backfills the hash.

Design decisions

Exchange pair as chunking unit (not fixed char size)
Preserving Q+A semantics keeps a user's question and the AI's answer together in one drawer, making search results coherent and enabling exchange-level retrieval. Fixed-char chunking — as used in project mining — would split exchange pairs arbitrarily and lose context. The fallback to paragraph-then-line-group chunking accommodates content without quote markers.
Extract mode as a dual path (exchange vs. general memory types)
Exchange mode serves conversation-as-conversation use cases; general mode supports decision/preference/problem tracking for non-conversational summaries like meeting notes and journaling. Making it a per-ingest flag (not a runtime toggle) gives each source consistent room classification, and the state file gates incremental re-runs per mode.
Per-message sweep as a secondary path, not primary
The sweeper catches individual messages that fall between file-level chunk boundaries without adding complexity to the primary miner. Separation of concerns keeps the file miner fast and simple while the sweep runs independently on JSONL sources, coordinating only through idempotent drawer IDs.
Wing auto-detection from path, fallback to dirname
Claude Code / Codex / Gemini conversations are API-sourced and group under wing_api by default, not per-project. A user-provided --wing always wins. For non-AI-tool sources, the dirname basename is more useful than a generic API label; _resolve_wing centralizes this fallback ordering.
Diary state file in ~/.mempalace/state/, not the user's diary dir
State files should not clutter user content directories or risk accidental edits. Keying by sha256(palace_path|diary_dir) lets multiple diary folders map to the same palace without conflicts, and enables incremental ingest plus in-place edit detection without re-hashing unchanged content every run.
⚡ Stale rows never coexist across schema versions

When NORMALIZE_VERSION bumps v1 → v2, _source_file_delete_ids (convo_miner.py:395) filters by extract_mode and removes every pre-v2 drawer for a source before upserting fresh chunks. This guarantees schema bumps apply uniformly — mixed-schema rows are impossible — and incremental reruns stay safe.

Data flow

Chat export files enter via scan_convos, are auto-detected and normalized to the >-prefixed transcript format by normalize.py, then chunked by convo_miner.py as either exchange pairs or general memory types. Each chunk is assigned a room via keyword scoring and a hall via cached config keywords, and gets a deterministic drawer ID — sha256(source_file|extract_mode|chunk_index)[:24]. On ingest, pre-v2 drawers are purged, then fresh chunks are upserted in batches with metadata (wing, room, hall, filed_at, normalize_version, extract_mode).

In parallel, the sweep path processes Claude Code JSONL message-by-message, with per-message drawer IDs keyed by (session_id, uuid) and timestamp-cursor logic to resume safely. Diary files follow a third path: split by ## entry headers, hashed for change detection, and upserted per-entry with closet packing for indexed summaries. All paths stamp ingest_mode (convos, sweep, or diary) and source_file for provenance. RFC 002 source adapters declare their transformations and are invoked through a PalaceContext facade that shields them from direct palace imports. Drawer and closet collections sit behind the RFC 001 backend abstraction, so mining is format-agnostic across Chroma, SQLite, and others.
