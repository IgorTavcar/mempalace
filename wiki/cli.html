Interfaces

CLI & Onboarding

The human entry point: init, mine, search, wake-up, run, status.

MemPalace's CLI (cli.py) dispatches 14 primary commands — init (setup + corpus detection), mine (three ingestion modes), search, wake-up (L0+L1 context injection), status, repair, and maintenance tooling. onboarding.py guides first-time users through mode selection (work/personal/combo), entity registration, and embedding-model choice, seeding the entity registry and a critical-facts bootstrap before mining begins. The whole flow is offline-first: every LLM step is best-effort and never blocks setup.

How it works

Init: four-pass onboarding

cmd_init (cli.py:230) orchestrates a four-pass setup. Pass 0 (_run_pass_zero, cli.py:106) detects corpus origin — AI-dialogue vs. code/docs — via heuristics plus optional LLM, storing the result in <palace>/.mempalace/origin.json so downstream entity detection knows whether "Echo" is a person name or an agent alias. Pass 1 (discover_entities) scans manifests, git authors, and prose for entity candidates, running optional LLM refinement when enabled. Pass 2 (detect_rooms_local) infers room structure from the folder hierarchy. Pass 3 (_ensure_mempalace_files_gitignored, cli.py:202) protects per-project files from accidental git commits (issue #185).

The command supports --yes (entity auto-accept), --auto-mine (skip the post-init prompt), --lang (entity language override), and three LLM controls (--no-llm, --llm-provider, --llm-api-key) with consent gates for external APIs (issue #26).

Corpus-origin two-tier detection

_run_pass_zero gathers Tier-1 samples by reading whole files up to per-file/total caps (100 KB per file, 5 MB ceiling, max 30 files) but skips mempalace's own artifacts so re-runs stay idempotent. Tier 1 calls detect_origin_heuristic for cheap regex matching (well-known AI brand terms plus turn markers). Tier 2, if an LLM is available, calls detect_origin_llm on trimmed samples (2 KB per sample, max 20 samples) but does not override the heuristic's likely_ai_dialogue/confidence fields — it only merges in the LLM's persona_names, user_name, and platform. Evidence trails are prefixed (Tier-1 heuristic: vs. Tier-2 LLM:) so origin.json audits which signal came from where. File-write failures are non-fatal; the in-memory result still feeds downstream classification. See corpus origin via LLM integration.

Mine command dispatcher

cmd_mine (cli.py:489) routes to three specialized miners based on the --mode flag:

  • projects (default) → miner.mine() for code and documentation.
  • convos → convo_miner.mine_convos() for Claude/ChatGPT/Slack transcripts, optionally auto-classifying into decisions/milestones/problems with --extract general.
  • extract → format_miner.mine_formats() for PDF/DOCX/XLSX/PPTX (requires mempalace[extract]).

All modes respect --wing, --include-ignored, --max-chunks-per-file (a Windows ONNX bad_alloc workaround), and --dry-run. Each miner catches MineAlreadyRunning and MineValidationError and surfaces them with friendly messages; SQLite integrity errors trigger repair-recovery instructions.

Wake-up context injection

cmd_wakeup (cli.py:712) instantiates a MemoryStack from layers.py and calls stack.wake_up(wing=args.wing). That concatenates Layer 0 (identity from ~/.mempalace/identity.txt, ~100 tokens) with Layer 1 (top 15 importance-scored drawers from ChromaDB, ~500–800 tokens), totaling roughly 600–900 tokens. Layer 1 groups drawers by room for readability and truncates long snippets. When --wing is passed, L1 filters to that wing only, enabling project-specific wake-up. The output is human-readable markdown suitable for direct injection into a system prompt or first assistant message.

Onboarding: interactive setup & entity seeding

run_onboarding (onboarding.py:390) prompts for six steps: (1) mode selection (work/personal/combo), (2) embedding-model choice (embeddinggemma multilingual default vs. minilm English-only; choice persists to config.json via set_embedding_model), (3–4) manual people & projects entry with relationship/role tagging, (5) optional file-based auto-detection of additional names, and (6) warnings about ambiguous names that collide with English words. It also generates AAAK bootstrap artifacts (_generate_aaak_bootstrap, onboarding.py:291) — aaak_entities.md (3-letter entity codes) and critical_facts.md — that teach the AI about the user's world from session one. quick_setup (onboarding.py:490) provides programmatic, non-interactive setup for tests and benchmarks.

Instructions CLI & skill routing

instructions_cli.py exposes five markdown instruction files (init, search, mine, help, status) via run_instructions (instructions_cli.py:16), which reads the .md from the instructions/ directory and prints it to stdout. These instructions are authored for AI-agent consumption and are invoked by the skill harness when users run /mempalace:init, /mempalace:search, and friends. The help.md file lists 19 MCP tools, CLI commands, auto-save hooks, and architecture in tabular form for quick reference.

Key concepts

Pass 0
Corpus-origin detection run during init to classify whether a corpus is AI-dialogue (Claude, ChatGPT, Slack exports). Two tiers: Tier 1 regex heuristics (always runs, no API) plus optional Tier 2 LLM refinement for platform/persona extraction.
Wake-up context
L0 (identity from ~/.mempalace/identity.txt) plus L1 (top 15 importance-scored drawers) injected into agent startup; ~600–900 tokens of critical facts without burning the full context window.
Embedding-model choice
Onboarding asks the user to pick embeddinggemma (multilingual, 300 MB, default) or minilm (English-only, 30 MB); the choice persists in config.json so future runs skip the prompt.
Three mining modes
Projects (code/docs), Convos (chat exports with optional auto-classification), and Extract (binary office documents); each feeds a specialized miner with different chunking and metadata strategies.
AAAK Dialect
Compressed notation (entity codes, emotion markers, pipe-separated fields) for efficient memory storage that stays readable to humans and LLMs; generated on init as aaak_entities.md.
Palace structure
Wings (top-level: projects or people), Rooms (topics/domains), Closets (summaries), Drawers (verbatim memories); Halls connect rooms within wings, Tunnels connect rooms across wings.
Hooks
JSON-based stdin/stdout system (session-start, stop, precompact) that auto-saves every 15 human messages or before context compaction; integrates with Claude Code and Codex harnesses.
Idempotent init
mempalace init produces the same output on re-run by filtering out mempalace's own artifacts (entities.json, mempalace.yaml) from corpus-origin samples so detection doesn't drift.

Implementation highlights

Tier 2 merge-fields logic. When the corpus-origin LLM tier runs, it does not override the heuristic's likely_ai_dialogue and confidence. Instead it conditionally merges primary_platform, user_name, and agent_persona_names if present, letting weak local models contribute without poisoning confident regex answers.

cli.py:145 · Tier 2 LLM merge preserves heuristic truth
# Heuristic owns: likely_ai_dialogue, confidence (do NOT touch).
# LLM contributes: primary_platform, user_name, agent_persona_names
if llm_result.primary_platform:
    result.primary_platform = llm_result.primary_platform
if llm_result.user_name:
    result.user_name = llm_result.user_name
if llm_result.agent_persona_names:
    result.agent_persona_names = list(llm_result.agent_persona_names)
💡 Insight: heuristic truth wins over a weak LLM

Tier 2 can extract persona names and platform, but its likely_ai_dialogue answer is discarded if it differs from a confident Tier 1 heuristic (cli.py:145). Per the PR #1211 review, this protects against weak local models (e.g. Ollama gemma4:e4b) flipping confident regex answers. The LLM is a scalpel, not a hammer.

Idempotent init via artifact filtering. _gather_origin_samples skips mempalace's own per-project files from corpus-origin sampling, so re-running init produces the same classification it did on the first run, preventing density drift.

cli.py:79 · skip mempalace artifacts during sampling
for filepath in files:
    if filepath.name in _MEMPALACE_PROJECT_FILES:
        continue  # Skip mempalace's own artifacts so re-runs stay idempotent
    if total_chars >= _PASS_ZERO_TOTAL_CAP:
        break
    try:
        with open(filepath, encoding="utf-8", errors="replace") as f:
            content = f.read(_PASS_ZERO_PER_FILE_CAP)
    except OSError:
        continue
⚠️ Gotcha: init is idempotent only because of the filter

Without the artifact-skip logic (cli.py:74–81), re-running init would pick up the entities.json and mempalace.yaml it wrote on the first run, changing corpus-origin density and producing a different classification. The filter is a non-obvious but critical detail for multi-user teams and CI systems.

Pass 0 memory bounds. Samples are capped at 30 files, 100 KB per file, and 5 MB total to fit in memory. Tier 2 LLM samples are further trimmed to 2 KB per sample and 20 samples max to fit finite context windows, preventing OOM or API-quota abuse. Mine post-init prompt (_maybe_run_mine_after_init, cli.py:409) reuses the pre-scan result to show a file-count and size estimate before asking "Mine now?", so the corpus tree is walked only once. LLM errors on init are caught and logged (cli.py:169) but never block init; a consent gate (issue #26) uses api_key_source to detect stray environment-variable APIs and blocks unless --llm-api-key was explicit or --accept-external-llm was passed.

⚡ Performance: wake-up never blocks and never bloats

Layer 1 enforces MAX_DRAWERS=15 and MAX_CHARS=3200 (~800 tokens), breaking early when the total exceeds the ceiling so wake-up stays in budget even with 10k drawers. stack.wake_up() also degrades gracefully when the palace is missing, empty, or ChromaDB reads fail (layers.py:96–97, 122) — the CLI command never crashes in a degraded state.

💡 Insight: multilingual is the default, English-only is opt-down

_ask_embedding_model (onboarding.py:88) defaults to embeddinggemma (300 MB multilingual) because cross-lingual cosine similarity under English-only MiniLM collapses to ~0.35 (essentially random). Non-English content silently breaks under MiniLM, so multilingual is the safe default even though it costs 10× more disk. See internationalization.

Edge case: corpus-origin evidence is immutable once prefixed

When _run_pass_zero detects that evidence lines are already prefixed (Tier-1 heuristic:), it skips re-prefixing (cli.py:158–167). This lets origin.json be read repeatedly without duplicating prefixes, but it also means evidence trails are frozen once written. Re-running --redetect-origin on mine (cli.py:498) only runs Tier 1 heuristics — no LLM — so evidence cannot be upgraded post-init.

Design decisions

Tier 2 LLM extracts platform & persona only; the heuristic owns AI-dialogue classification
A weak local LLM can hallucinate platform/persona, but its answer to "is this AI-dialogue?" conflicts with a confident heuristic. PR #1211 settled on the LLM as a specialist (extracts what it's pre-trained on: Claude vs. ChatGPT) and the heuristic as a conservative gate (regex marks are hard signals). This avoids false negatives that would break downstream entity detection.
Idempotent init via artifact filtering, not checksum/mtime guards
Simpler and more robust than tracking what was written. By skipping mempalace's own files from corpus-origin sampling (cli.py:74–81), the heuristic sees the same inputs on re-run and produces the same output — across machines, containers, and git clones, with no state files.
Multilingual embedding as the default, not English-only
Non-English content stored under English-only MiniLM fails silently — cosine similarity collapses to ~0.35. Multilingual embeddinggemma costs 10× disk but guarantees cross-lingual recall; --minilm is the opt-down for slow links or English-only users. Safe default beats fast default.
Wake-up injects L0+L1 as a fixed ~600–900 tokens, never variable
Predictable context cost so users know exactly how many tokens are burned before the first AI response. L1 truncates hard at MAX_CHARS=3200 so even a palace with 10k drawers won't exceed budget, leaving 95%+ of the context window free.
Pass 0 is non-fatal; LLM failures fall back to heuristics silently
Init must work offline and in CI without an external API. The LLM tier is always optional and best-effort (cli.py:142); users see at most a one-line message if the LLM is missing and never see "init blocked waiting for API." This mirrors the no-API-key-required promise of the whole system.

Data flow

When a user runs mempalace init <dir>, the flow is:

  1. MempalaceConfig() loads config.json or defaults.
  2. _gather_origin_samples reads up to 30 files (skipping mempalace artifacts) for corpus-origin detection.
  3. _run_pass_zero runs Tier 1 heuristic regex, optionally runs Tier 2 LLM (merging fields, not replacing), and writes <palace>/.mempalace/origin.json.
  4. discover_entities scans for people/projects/topics, optionally LLM-refined, and receives the corpus_origin dict so it knows whether "Echo" is a person or an agent.
  5. confirm_entities prompts the user to validate, writes entities.json to the project root, and syncs to the global entity registry.
  6. detect_rooms_local infers rooms from folder structure.
  7. _ensure_mempalace_files_gitignored adds mempalace.yaml and entities.json to .gitignore.
  8. _maybe_run_mine_after_init offers to mine immediately, reusing the pre-scan result.

On wake-up, MemoryStack loads identity.txt (L0), queries ChromaDB for the top-weighted drawers (L1), concatenates them, and prints markdown for prompt injection. On mine <dir>, the dispatcher routes to one of three miners; each produces drawers (text + metadata) upserted into ChromaDB. On search "query", the searcher builds where-filters from wing/room flags, queries ChromaDB semantic similarity, and returns ranked results. Throughout, the CLI respects --palace to override the default palace path (cli.py:242), enabling multi-palace workflows.
