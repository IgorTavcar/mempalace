Entity System

Auto-detecting and disambiguating the people, projects, and systems in your text.

MemPalace's entity system detects and classifies proper nouns — people, projects, topics — from your content using a two-pass, signal-based approach. Pass 1 extracts candidates via i18n-aware regex patterns and a COCA content-word filter; pass 2 scores them on contextual signals (dialogue markers, pronouns, action verbs, versioning) and classifies under a two-signal-category rule. A persistent EntityRegistry seeds from onboarding, learns high-confidence candidates, and optionally researches unknowns via Wikipedia. Corpus-origin detection separates AI-dialogue agent personas from real people before classification, and the resulting entities key wings and feed hallway computation for entity-centric navigation.

How it works

Detection runs in two passes over text, gated by a corpus-origin check that protects against misreading narrative prose as AI dialogue. Everything downstream — closet pointers, hallways, and search — depends on accurate entity output.

Extraction & candidacy (Pass 1)

Extraction begins with language-aware regex patterns loaded from i18n/*lang*.json entity sections. Single-word candidates match character classes that vary per script (ASCII [a-z], Latin+diacritics, Cyrillic, Devanagari, …); multi-word candidates capture phrases through separate patterns. All matches pass a union of locale-specific stopwords to eliminate articles and particles. The COCA content-word filter then removes ~600 common English words (Code, Line, Phase, Note) that appear capitalized but are never entities.

  • The multi-word path bypasses COCA filtering, preserving compounds like Claude Code.
  • Only names with frequency ≥ 3 advance to scoring; singletons are treated as noise.

Signal scoring (Pass 2)

Each candidate is scored across six signal types into a person_score and a project_score, each carrying human-readable signal strings for later review:

  • Dialogue markers — colon-prefix speaker tags, weighted 3× per match.
  • Person verbs — actions like said, asked, weighted 2×.
  • Pronouns within a 3-line window, weighted 2×.
  • Direct address, weighted 4×.
  • Versioned / hyphenated forms (project signal), weighted 3×.
  • Code-file references (project signal), weighted 3×.

A second-pass heuristic guards the dialogue signal: bare colon-prefix patterns must occur 2+ times before counting, since real speakers repeat but metadata lines like Created: 2026-04-21 do not.

Classification with the multi-signal requirement

Classification requires orthogonal evidence. A person candidate must exhibit signals from at least two different categories (dialogue, action, pronoun, direct-address) with person_score ≥ 5, or show a strong pronoun-only signal (pronoun_hits ≥ 5 and pronoun_hits / frequency ≥ 0.2). Projects are classified when project_score dominates; mixed signals default to uncertain for user review. Confidence is capped at 0.99 and calibrated as person_confidence = 0.5 + person_ratio * 0.5.

⚠️ Gotcha: syntactic artifacts masquerading as people

A word like Click appearing 15 times (“Click, click, click, they filled…”) can match the person-verb pattern repeatedly, amassing a high person_score from a single signal category. The two-signal-category rule (entity_detector.py:404) blocks this unless Click also shows dialogue markers, pronouns, or direct address. Without it, action-verb frequency alone would produce false positives.

Corpus-origin detection & persona reclassification

Before detection feeds the taxonomy, corpus-origin detection determines the platform and any agent-persona names. Tier 1 (heuristic, always on) counts unambiguous AI brand terms (Claude Code, ChatGPT, MCP, LLM) and ambiguous terms (Claude, Opus, Haiku, Gemini) under a co-occurrence rule. Tier 2 (optional LLM) uses model knowledge to extract the persona names a user has assigned to their agent instances. When corpus_origin is passed to detect_entities, candidates matching agent_persona_names are moved out of people/uncertain into an agent_personas bucket and retagged type="agent_persona", preventing downstream drawer-allocation errors such as family/relationship inference on an AI.

EntityRegistry: three-tier persistence

The registry at ~/.mempalace/entity_registry.json stores entities by source priority: (1) onboarding (confidence 1.0, user-explicit), (2) learned (inferred from sessions, auto-added at high confidence), (3) wiki (researched via Wikipedia, optional network call). Lookup returns type, source, confidence, and canonical name for aliases. Ambiguous words like ever and grace carry an ambiguous flag; when context is supplied, _disambiguate() scores person-context patterns (Said, with, possessive 's) against concept-context patterns (have you, would ever) and returns the higher-scored type. See Security & Privacy for the network gating on Wikipedia research.

Integration: closets & hallways

During mining (palace.py), each drawer's content window is scanned for entity candidates with the same i18n-aware patterns. Proper nouns appearing 2+ times are extracted, COCA-filtered, ranked by frequency (max 5), and stored in closet pointer lines as the 2nd pipe-separated field. In hallways.py, entities are extracted again from drawer contents to compute entity-pair co-occurrence graphs within each wing: every pair of entities sharing a drawer increments a counter, rooms are tracked, and high-traffic pairs become hallway nodes labeled like “Alice ↔ Bob (co-occur in 12 drawers across 3 rooms)”. Entities thus key the entire wing-navigation model.

Key concepts

COCA content-word filter
Tier 2 linguistics cleanup: a frozenset of ~600 common English words (code, phase, brutal, line, note) that appear capitalized but are not proper nouns. Blocks false-positive detection on sentence-start words. Multi-word candidates intentionally bypass this filter to preserve compounds like Claude Code.
Two-signal-category rule
A person must exhibit signals from two different categories (dialogue, action, pronoun, direct-address) to classify confidently. Single-category hits (e.g. only action verbs) are downgraded to uncertain, preventing patterns like “Click, click, click…” from being read as the person-entity Click.
Corpus-origin detection
Two-tier system (Tier 1 heuristic + optional Tier 2 LLM) that decides whether a corpus is AI-dialogue vs narrative. Tier 1 uses brand-term regex (unambiguous: Claude Code; ambiguous: Claude) with co-occurrence rules. Tier 2 extracts platform identity and agent-persona names. Persona-matched candidates are reclassified people→agent_personas to prevent false family/relationship inference.
Non-Latin word boundaries
Locales with combining-mark scripts (Devanagari ा ी, Arabic ـَ ـِ, Thai, Khmer) declare boundary_chars in their i18n entity sections. These expand Python's default \b to a lookaround-based boundary that preserves marks, so names like अनीता match correctly instead of truncating to अनीत.
EntityRegistry
Persistent ~/.mempalace/entity_registry.json storing three tiers: onboarding (user-confirmed), learned (high-confidence session detections), and wiki (Wikipedia-researched, local-only by default for privacy). Supports ambiguous-flag disambiguation, alias tracking, and relationship metadata.
Closet pointer entities
Proper nouns embedded in closet lines as the 2nd pipe-separated field. Detected via i18n-aware patterns over a content window; entities appearing 2+ times are extracted (max 5), deduped, and ranked by frequency. Feeds palace-level searching and hallway computation.
Agent personas
Names the user has assigned to AI agents they converse with (e.g. Echo, Sparrow, Claude-instance-2). Extracted by Tier 2 (LLM) during corpus-origin detection. When corpus_origin context reaches detect_entities, matching candidates are reclassified from people/uncertain into a separate agent_personas bucket.
Disambiguation context
For ambiguous words that are also common English (ever, grace, may, Rose), EntityRegistry._disambiguate() checks surrounding context against person-context patterns (said, with, 's) and concept-context patterns (have you, if you, would). Context-derived confidence adjusts the final decision.

Implementation highlights

The COCA filter is a lazily-loaded, cached frozenset — costly to build once, then O(1) on every lookup, and degrading gracefully to a no-op filter if its data file is missing.

entity_detector.py:62 · COCA filter lazy-load cache
@functools.lru_cache(maxsize=1)
def _get_coca_filter() -> frozenset[str]:
    data_path = Path(__file__).parent / "data" / "coca_content_words.json"
    try:
        raw = json.loads(data_path.read_text(encoding="utf-8"))
        words = raw.get("words", [])
        return frozenset(w.lower() for w in words if isinstance(w, str))
    except (OSError, json.JSONDecodeError, AttributeError, TypeError):
        return frozenset()

Dialogue scoring validates bare colon-prefix patterns so single-line metadata can't impersonate a speaker tag:

entity_detector.py:298 · dialogue marker validation
# The bare `^NAME:\s` colon-prefix pattern matches metadata lines like
# `Created: 2026-04-21`, so we require >= 2 hits for it to count as dialogue
# (real speaker markers repeat; single-line metadata doesn't).
for rx in patterns["dialogue"]:
    matches = len(rx.findall(text))
    if matches == 0:
        continue
    is_bare_colon = rx.pattern.endswith(r":\s") and not rx.pattern.endswith(r"[:\s]")
    if is_bare_colon and matches < 2:
        continue
    person_score += matches * 3

The corpus-origin co-occurrence rule is the single line that prevents narrative prose from registering as AI dialogue:

corpus_origin.py:209 · ambiguous-term co-occurrence rule
# Ambiguous terms ('Claude' as a French name, 'Gemini' as a zodiac sign,
# 'Haiku' as a poem form) only count if the corpus also has an unambiguous
# AI signal. Otherwise we'd false-positive on French novels, astrology
# forums, poetry corpora, llama-rancher journals, etc.
has_ai_context = total_unambiguous > 0 or turn_hits > 0
counted_brand_hits = total_unambiguous + (total_ambiguous if has_ai_context else 0)
🔒 Security: co-occurrence rules out literal false positives

A French novel with a character named Claude, an astrology corpus full of Gemini, or a poetry corpus about haiku could all false-positive as AI-dialogue. The co-occurrence rule (corpus_origin.py:215) solves it: Claude alone scores low; Claude + ChatGPT triggers high. This prevents misclassifying personal narratives as AI-dialogue — whose downstream effect would be marking real family members as AI personas.

More highlights — persistence, merging & closet extraction
  • Atomic registry writes (entity_registry.py:324) — save() serializes to a .tmp sibling, fsyncs, then os.replace to target (and fsyncs the parent directory on ext4+). The previous registry survives a crash mid-write rather than truncating to empty.
  • Field merging in Tier 2 (cli.py:135) — when the LLM augments the heuristic, likely_ai_dialogue and confidence stay from Tier 1; Tier 2 contributes only primary_platform, user_name, and agent_persona_names. Evidence is prefixed (Tier-1 heuristic:, Tier-2 LLM:) for audit.
  • Closet entity extraction & dedup (palace.py:266) — _candidate_entity_words() scans a 5000-char window, counts frequencies, applies stoplist + COCA filter, keeps count ≥ 2, sorts by frequency, caps at 5. Dedup is implicit via the frequency dict.
💡 Insight: recall > precision for compounds

Single-word extraction applies the COCA filter to suppress Code, Phase, Note — but multi-word candidates are deliberately not filtered (entity_detector.py:217). This preserves Claude Code (where bare Code would be suppressed) and lets legitimate compound project names escape the filter. A conscious trade: favor recall (don't miss Claude Code) over precision (a false positive on bare Code).

💡 Insight: pronoun-only classification needs a high ratio

A diary protagonist mentioned 100 times and referenced with pronouns 20 times classifies as a person via the pronoun signal alone — bypassing the two-signal rule — only if pronoun_hits ≥ 5 and pronoun_hits / frequency ≥ 0.2 (entity_detector.py:416). That 20% ratio rejects common sentence-start words (Never, Before) that incidentally sit near pronouns, while still catching true diary protagonists.

Design decisions

Three-tier entity registry (onboarding > learned > wiki)
Onboarding (confidence 1.0) seeds ground truth the user explicitly confirmed; learned entities (auto-added from sessions) require high confidence (>0.75) to avoid proliferation; wiki is research-only and network-gated, never auto-added. The ordering honors user intent first, high-confidence inference next, optional external research last — matching the local-first, zero-API philosophy.
Corpus-origin detection before entity taxonomy
Determining platform and agent-persona names before detect_entities runs prevents catastrophic downstream errors — an AI instance named Echo shouldn't populate family/relationship drawers. Tier 1 always runs (offline); optional Tier 2 confirms ambiguous cases. Early detection lets classification skip agent personas entirely.
COCA content-word filter + multi-word bypass
Balances precision (suppress Code as a false-positive entity) against recall (preserve the Claude Code compound). Real project/person names tend to be multi-word (Alice Chen, Cloud Run) while accidental false positives are single words (Code, Phase), so the bypass aligns the filter with observed reality.
Two-signal-category rule over single-category scores
A single syntactic pattern can fire repeatedly on noise (Click, Click, Click) and amass a high score. Requiring two orthogonal categories (dialogue + pronoun, or action + direct-address) enforces independent evidence. A low false-positive rate on closed corpora beats high recall on noisy input.
Field merging (not replacement) in Tier 2 LLM
Tier 1's likely_ai_dialogue and confidence are heuristic ground truth based on known signal densities; a weak LLM (e.g. Ollama gemma2) can be wrong, so it never overrides them. Tier 2 contributes only persona extraction — fields Tier 1 never computes — and evidence is merged with prefixes for audit.
Local-only EntityRegistry research by default
Wikipedia lookup requires explicit allow_network=True; otherwise research() returns unknown locally. No data leaves the machine unless the caller asks, honoring privacy-by-architecture. See Security & Privacy.

Data flow

Raw text flows through extract_candidates() (i18n regex, COCA filter, frequency ≥ 3) yielding candidates. Each enters score_entity() (dialogue, pronouns, verbs, versioning signals), then classify_entity() (two-signal-category rule → person / project / uncertain). Detected entities feed confirm_entities() for user review, and confirmed {people, projects, topics} seed EntityRegistry.seed() and mempalace/entities.json.

During mining, corpus-origin detection (Tier 1 heuristic + optional Tier 2 LLM) runs first, producing agent_persona_names that are passed to detect_entities via the corpus_origin kwarg — triggering _apply_corpus_origin() to reclassify matching candidates into the agent_personas bucket. Drawer content then passes through palace.build_closet_lines(), which extracts entities via _candidate_entity_words(), dedupes on frequency ≥ 2, COCA-filters, and embeds them as the 2nd pipe field of closet lines. Those entities feed hallways.compute_hallways_for_wing(), which counts entity-pair co-occurrences, ranks by room frequency, and builds entity-centric navigation graphs. Meanwhile EntityRegistry.learn_from_text() auto-discovers new high-confidence candidates during sessions, and entities plus optional Wikipedia lookups and confirmations persist to ~/.mempalace/entity_registry.json via atomic writes.
